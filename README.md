# ok-lqsn · ok篮球少女

> 《篮球少女：飞跃巅峰》PC 版自动训练工具。**看屏幕识字 → 按规则决策 → 点击**，不读内存、不改游戏数据。
> 版本：**v0.1**（2026-11-23）　｜　当前内置方案：**百目鬼训练**　｜　仅供个人学习交流。

本项目基于 **[ok-script](https://github.com/ok-oldking/ok-script)** 框架构建（官网：<https://ok-script.com/>）。
按框架许可证要求在此署名并给出链接：ok-script 由 ok-oldking 开源，采用 Apache-2.0 + Commons Clause 许可；本项目未修改框架本体，仅在其上实现任务与规则配置。

## 一、它是什么 / 不是什么

| | |
|---|---|
| **是** | 一个用**计算机视觉**驱动的循环训练脚本：截屏 → OCR 识字 + 颜色/位置识别 → 按规则选技能/选项 → 模拟点击 |
| **不是** | 内存读写器、注入器、修改器。**不读取游戏内存，不修改任何游戏数据，不 hook 进程** |
| **目标** | **速刷笔记**（每周找「笔记 / 继承」）、尽可能多人多器材地循环训练 |
| **做不到** | 追求极限高分、自动配队（见下方「边界」） |

**风险说清楚（务必先读）**

1. **账号风险**：任何自动化操作都可能违反游戏用户协议。请用小号/自担风险，本项目不对账号后果负责。
2. **前台占用**：点击走系统前台输入（Pynput），运行时**不要动鼠标键盘**，也不要用远程桌面切焦点；焦点被抢会导致点击被静默丢弃。工作台启动后会自动最小化让出前台。
3. **识别不是 100%**：OCR 会漏字、动画帧会误判。遇到没见过的页面默认**暂停等人**，不会乱点；但复杂场景仍可能点错，请看着跑几轮再放无人值守。
4. **只认 1920×1080**：分辨率/缩放比例变了要重新校准坐标。
5. **外用风险**：不要把打包产物拿去分发、商用或用于作弊牟利（框架许可证也禁止此类用途）。

## 二、用法

### 2.1 release 版（推荐，不用装 Python）

1. 解压 `ok-lqsn-v0.1-win64.zip` 到一个**纯英文路径**（如 `D:\ok-lqsn`）。
2. 先**手动登录游戏并选好**：队友、笔记、器材（本工具不负责选，见「边界」）。
3. 双击 `ok-lqsn.exe` 打开工作台。
4. 点「启动游戏」（游戏没开时）→ 点「只跑训练（游戏已开）」。
5. 运行中工作台会自动最小化；要停止就点任务栏的工作台 →「停止」（只停脚本，不退游戏）。
6. 每轮结束在 `logs/summary_*.txt` 写摘要，`logs/audit/` 留每次决策的截图与判定文本。

### 2.2 源码版（开发/改规则）

```bat
:: 1. 环境：Python 3.12 + 依赖
python -m venv .venv
.venv\Scripts\pip install -r requirements.txt

:: 2. 启动工作台
run_workbench.bat        :: 等价于 python -m workbench

:: 3. 无界面跑一轮
.venv\Scripts\python.exe -m ok run_task -c src.config:config AutoTask
```

**先读术语表**：[`docs/17-术语表.md`](docs/17-术语表.md) —— 训练项 / 训练项页 / 训练项详情 / 经理增益 / 读数，全项目只有这一套叫法，日志和报告里的词都能在这张表里查到。

详细的架构、页面地图、规则配置手册见 [`docs/`](docs/)（尤其 `docs/03-规则配置手册.md`、`docs/08-工作台.md`、`docs/13-规则怎么改.md`）。

## 三、方案管理（v0.1 新增）

把整套局内规则做成一份**方案**：`profiles/<名字>.json`，内容是 `config/strategy.yaml` 的**逐字快照（含注释）**。

- 当前方案：**百目鬼训练**（已内置并设为默认）。
- 工作台左侧「训练方案」区支持：**切换（选中即应用）/ 保存改动 / 另存为 / 重命名 / 删除 / 导入 / 导出**。
- **导入导出就是一个 .json 文件**，可以直接发给别人；导入后选中即生效。
- 切换方案会把该方案的原文写回 `config/strategy.yaml`，因此注释不会丢，所有现有读取链路无需改动。
- 当前生效方案记在 `config/active_profile.json`。

> 运行中禁止切换方案（任务已缓存配置，运行中改了也不生效）。

## 四、当前规则（百目鬼训练）

一句话：**尽可能多人、多器材训练，每天（含周六/周日）先去步行街扭蛋看有没有「笔记 / 继承」，有就拿，没有就退回继续训练或去公园补精力。**

| 项 | 当前值 / 行为 |
|---|---|
| 笔记 | 每天先探「出行 → 步行街 → 扭蛋三选一」，命中【笔记 / 继承】就选；没有则右上角连点两次退回 |
| 周日 | 也检查笔记（休息日无训练时先探笔记，再按原规则去公园） |
| 训练项页打分 | 队友数 × 1.0 + 器材分（普通 0.5 / 金 1.0 / 彩 1.5），**球队经理单独按 1.5** |
| 失败率 | 30% 以内可赌，按期望收益打折；全部 >30% 且商店没药时改练「意识」 |
| 等级 | 不计分（只记录便于人工复核） |
| 精力 | 低于 45 时「意识」加权（不耗精力还回精力），保证周一到周六都能练 |
| 商店 | 只买 0 元馈赠 + 精力 <50 时买 50 以下饮料；永远留 120 金买笔记；**周日不进店** |
| 周末 | 没训练就去公园回精力（野餐 > 划船 > 散步）；周日的休息就是去公园 |
| 未知页 | 默认暂停等人，不盲点 |

全部细节和每条规则背后的玩家口径（含日期）都写在 [`config/strategy.yaml`](config/strategy.yaml) 的注释里。

## 五、边界（v0.1 明确做不到）

- **只做速刷笔记**，追求极限高分做不到。
- **没有做自动选人 / 选笔记 / 选器材**；只能**人工选好之后让它循环跑**。
- **借用次数用完后要人工调整器材**，脚本不会自动换器材。
- **目前只有「百目鬼训练」这一套规则配置**；其他队伍没有，也不知道怎么配（不同主训 → 不同路线 → 选项/事件分支都不同，框架里 `routes` 段预留了空位但尚未填写）。
- 只支持 PC 客户端（`k3_windows_ob.exe` / `UnityWndClass`），1920×1080。

## 六、给后续 Agent 的建议：怎么把自然语言变成规则配置

这段是这几天实际调试过程的提炼，供接手的 agent 参考。

1. **先要证据，不要猜。** 玩家说「周日没看笔记」，先去日志找当天走了哪个分支，再决定改哪里。真正的根因是「探笔记被塞在『有训练且精力够』分支里，周日没训练直接去公园」——不看日志就会误修成「公园优先级」。
2. **把模糊词量化成可测条件。** 玩家说「人多一点」「器材好一点」，要翻译成：`队友数 × teammate` + `Σ 器材档位（普 0.5 / 金 1.0 / 彩 1.5）`，并写进 yaml 注释标明来源（例：`manager_weight: 1.5  # 玩家 2026-11-23 22:14`）。
3. **一次只改一条规则，配离线单测。** 每改一处都加 `tools/test_*.py` 用例（用桩对象 + 合成帧，不打游戏），再跑全回归 10 套。
4. **上真截图做「零误伤扫描」。** 用 `screenshots/auto/` 里积累的 200+ 张真实帧离线 OCR + 分类，对比改动前后的判定差异。只允许目标帧变化；非目标帧变化必须先解释清楚（是纠正还是误伤）。
5. **玩家的现场纠正优先于代码注释。** 注释会过时（例：「经理不算队友」后来被改成「经理算队友并加权 1.5」）。以最近一次玩家原话为准，并在注释里保留变更链。
6. **把「为什么会这样」写进日志。** 每条关键决策都打一行（`[探笔记]`、`判定 选项 但底部有成排黄卡片 → 按事件页处理`、`队友…经理…→ 得分…`），否则出了问题无法复盘。
7. **留下可人工复核的证据。** `logs/audit/<run_id>/W<周>D<星期>/` 每次决策存截图 + OCR 原文 + DECIDE 文本；摘要写清训练次数/探笔记次数。玩家会逐条核对。
8. **不懂就问，但先给 A/B/C/D 选项。** 玩家偏好结构化澄清；重大改动（换框架 GUI、改核心计分口径）先列方案再动手。
9. **遇到新页面先分类再点击。** 页面被误判后，兜底点击往往空转几百步。优先修 `_classify` 的规则，再考虑加点击兜底。

## 七、还有什么值得补充（我的建议）

- **回归样本库**：把 `screenshots/auto/` 里确认过分类的帧整理成带标签的测试集，以后改识别规则直接跑，不用每次全量 OCR。
- **方案校验器**：导入时校验 yaml 语法与关键键（如 `core_score.teammate`），坏配置在导入时就报错，别等到跑一半才崩。
- **运行前自检**：开跑前确认「选人/笔记/器材页没有空槽」+ 游戏在前台，避免白跑一轮。
- **队伍方案**：等你摸清其他主训的路线，把 `routes.<角色名>` 填起来，再存成第二份方案（工作台「另存为」即可）。
- **文档同步**：`docs/00-原开发说明.md` 是旧版开发笔记，`docs/` 下 01~13 是分主题手册；两者有少量重叠，后续可合并。
