# 篮球少女：飞跃巅峰 —— 自动训练项目（bsg-auto）

> 用 **ok-script 3.0** 框架，给 PC 版《篮球少女：飞跃巅峰》（原生 Windows 客户端，`k3_windows_ob.exe` / `UnityWndClass`）
> 做一个「看屏幕 → 认出当前页面 → 按可配置规则决定点哪个 → 点下去」的自动训练工具。
>
> 这个目录是**重新整理过的正式项目**：代码沿用上一版验证过的实现，文档全部重写，
> 目标是让任何人（或任何一次新的 AI 会话）只看本目录就能接着干。

## 一句话现状（2026-11-23 09:00）

**整段训练已经能无人值守跑完：大厅 → 训练 → 启程 → 选人 → 第1周…第7周（含比赛日/出行/事件/加强训练/行为卡）→ 训练评分 → 恭喜获得 → 训练结束 → 回大厅。**

已能**冷启动**：游戏没开、连启动器都没开时，`tools/start_game.py` 会把启动器拉起来 →
点「启动游戏」→ 关公告弹窗 → 点「点击进入」→ 进大厅，之后交接给训练任务。
上次非正常退出时走「训练中 → 训练确认 → 继续训练」恢复中断。

**选人页没选满会自己停下来**：选择队友/笔记/器材页上出现「金色粗边框 + 白底 + 黄加号」
的空槽时，先点一次「自动选择」补满；补不上就截图 + 通知 + 暂停，**不会自己开训**。
规则在 `config/strategy.yaml` → `tuning.pick_slots`（详见 docs/04 #52）。

**发布后用的是工作台**（不是开发调试台）：双击 `run_workbench.bat`，能看配置、自检环境、
启动游戏、跑训练、看实时日志。见 `docs/08-工作台.md`。

**两种资源已经分清**（之前混用害了一整周）：
- 局内「精力」⚡ a/**130** —— 训练消耗，只靠局内事件和周末公园恢复，驱动「今天训练还是休息」
- 局外「体力/专注」a/**150**（可溢出，实测读到过 221/150）—— 开训练的门票，只能喝药水补，
  **每次训练只消耗 30，所以 ≥30 就不补**

**训练核心的「编队打分」修好了，但采样成功率还只有一半**（48 次采样里 23 次 0 帧可用）。
根因是点开技能徽章后编队面板盖住技能列，靠「这页还像不像核心页」筛帧必然失败。
正解是用模板/颜色匹配技能角标，已排进 `docs/06-下一步.md` 的 P0-2。

**调试方式已换成框架自带的 MCP 接口**，不再「改代码→手动开游戏→肉眼看」盲调。
见 `docs/07-框架与MCP调试.md`。

## 怎么跑

运行环境沿用上一版目录里的虚拟环境（`../ok-bsg/.venv`，已装好 PyTorch/onnxocr 等依赖）。

### 从零开始（游戏没开、甚至启动器没开）

```bash
# 一条命令：起启动器 → 点「启动游戏」→ 关公告弹窗 → 过标题页 → 进大厅
../ok-bsg/.venv/Scripts/python.exe tools/start_game.py

# 进大厅后直接接着跑主流程（等价于 run_auto.bat）
../ok-bsg/.venv/Scripts/python.exe tools/start_game.py --auto
```

实测冷启动到大厅约 30 秒：启动器 4s → 点「启动游戏」1s 拉起 `k3_windows_ob.exe`
→ 健康游戏忠告（等它自己过）→ 版本检查 → **公告弹窗（模板匹配右上角 ×）**
→ 标题页点「点击进入」→ 大厅（命中 5 个锚点后停止点击）。

| 参数 | 作用 |
|---|---|
| `--auto` | 进大厅后自动跑 AutoTask，一路训练到收工 |
| `--dry-run` | 只观察不点击，用来对账识别结果 |
| `--timeout N` | 进大厅阶段的超时（默认 240s） |
| `--no-shot` | 不保存过程截图（默认存 `logs/start_game/<时间戳>/`） |

两条补充工具：

```bash
../ok-bsg/.venv/Scripts/python.exe tools/ocr_now.py --save   # 当前画面 OCR 全量文字 + 相对坐标
```

### 游戏还开着、但停在中途（上次非正常退出）

不用重启游戏，直接跑主流程：

```bash
../ok-bsg/.venv/Scripts/python.exe -m ok run_task -c src.config:config AutoTask
```

它会自己接上：大厅点右下角**「训练中」** → 弹出**训练确认** → 点**「继续训练」**
恢复中断的那一轮（周次、局内精力都沿用上次，不是新开一轮）→ 训练核心 → …

顺带能清掉的遮挡页：**游戏内公告浮层**（模板匹配右上角 × 关掉）、
**炒股小游戏**（选股 → 确定；走势屏 → 卖出）。

### 推荐：走 MCP（可复现，能看每一步）

```bash
# 1. 起服务（常驻，一次就够；起了就别再开 GUI，GUI 会顶掉它）
../ok-bsg/.venv/Scripts/python.exe -m ok mcp --config src.config:config

# 2. 改完代码 → 编译 → 热重载
../ok-bsg/.venv/Scripts/python.exe -m py_compile src/tasks/AutoTask.py
../ok-bsg/.venv/Scripts/python.exe tools/mcp_client.py reload --ids src.tasks.AutoTask.AutoTask

# 3. 跑一轮
../ok-bsg/.venv/Scripts/python.exe tools/mcp_client.py run_task --file tools/run_auto.py

# 4. 看黑匣子（每步的页面/精力/点击理由都在里面）
grep -E "页面：|点击「|ERROR" logs/mcp/<run_id>/run.log | tail -40
```

完整工具清单、`run_task` 的文件契约、热重载坑、截图方式选择，见 `docs/07-框架与MCP调试.md`。

### 老办法（双击 .bat，肉眼盯）

```bat
run_check.bat        :: 只读体检，一个按钮都不点。改完规则先跑这个
run_coreprobe.bat    :: 训练核心页专用：数编队，不点决定
run_auto.bat         :: 主流程
```

注意：**游戏窗口不能最小化**（最小化时 WGC 抓不到，返回 −32000 矩形），
挡在别的窗口后面也不行 —— 点击是真实鼠标事件（Pynput），窗口必须在前台。
想把显示器关掉跑通宵，要把 `src/config.py` 的 `capture_method` 改成
`['BitBlt_RenderFull', 'BitBlt', 'WGC']`（WGC 在显示器断电后会永久阻塞）。

> **和 `../ok-bsg/` 的关系**：老目录保留三样东西——虚拟环境、963 张录制原图（1.5G）、历史截图与日志。
> **代码与配置以本目录（bsg-auto）为准**，老目录不再修改。

要在别的机器上重建环境，见 `docs/05-素材与证据.md` §6。

## 三条铁律（都是踩出来的）

1. **先看再猜。** 不许凭想象写页面内容、按钮名字、技能名。认不出就截图标出来问。
2. **第一次调新页面用单步任务**，一步一截图，不要循环连跑 —— 连跑时点到别的窗口或进未知页会连错。
3. **认不出就停**，绝不「兜底乱点」。历史上两次严重翻车（进了游戏厅拼图、把「出行」按钮当事件选项）
   都是兜底逻辑太主动造成的。
