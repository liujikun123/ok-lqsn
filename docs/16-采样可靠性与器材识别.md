# 16 采样可靠性与器材识别（2026-11-24 第二轮）

> 起因：玩家问「采样失败问题你再看看，有借助框架吗」。
> 结论：**「采样失败 32%」是我上一轮误读出来的数字；真正的采样缺陷在器材识别上，
> 而那里确实一直没用框架、也没用对颜色**。本文记录排查过程与修复。

---

## 1 「32% 采样失败」是怎么来的（已证伪）

上一轮我把日志里的 `编队采样 4/6 帧有效（试了 4 次）` 读成了「6 帧里丢了 2 帧」。
实际读代码就知道不是：

```python
if used >= min_frames and len(pcts) >= 2 and len(name_sets) >= min_frames:
    break          # min_frames 默认 4 —— 采够 4 帧就收工
```

`tries == used == 4`，说明**每一帧都通过了判据、第 4 帧提前收工**，没有废帧。

交叉验证：

| 证据 | 数值 |
|---|---|
| 日志 `编队采样 4/6 帧有效` | 260 次（另 1 次 5/6），`试了 4 次` = 4 帧全用上 |
| 日志 `采样 0 帧有效` | **0 次** |
| 审计 `有效采样：True/False` | **397 / 397 全 True** |
| 摘要 `采样失败 N 项` | 全部 **0 项** |

也就是说：**技能级采样失败率 0%，帧级丢失 0 帧**。这个方向没有问题，不需要改。

## 2 真问题：器材（支援卡）识别一直全灭

### 2.1 现象

实跑日志 263 次采样，`器材 0` 出现 **258 次**（另 4 次读到 6 张、2 次读到 2 张，都是误检）。
而画面里明明每场都摆着 1~3 张卡（玩家原话：「中间一个器材（鞋子），不是很明显吗」）。

旧 `find_cards` 的 docstring 甚至把这件事当成正常现象写进去了：
「离线跑 122 帧：0 张 108、1 张 9、2 张 3、3 张 2」。

后果：`core_score.equipment`（普通 0.5 / 金光 1.0 / 彩光 1.5）**从来没被加进过排名**，
每场训练白丢 0.5~4.5 分 —— 这是 9000 分缺口的实打实来源之一。

### 2.2 根因

旧实现用「金色掩膜」找卡：

```python
mask = (r > 205) & (g > 155) & (b < 160) & ((r - b) > 45)
```

**木地板本身就是橙黄色**，整片地板都满足这个条件。实测单帧：

```
ROI 内 mask 覆盖率 32.41%
最大连通域 639x167（= 整个 ROI 宽度）
```

卡片和地板连成一大块，被「最大宽度 0.14w」的尺寸过滤直接丢掉 → 0 张。

### 2.3 修法（`src/core/cards.py` 重写）

1. **双掩膜**：`金边（b<105 把地板分出去）` ∪ `高饱和色块（彩光卡用）`；
2. **形态学核随分辨率缩放**（1600 宽 → 13，1920 宽 → 17）；
3. **IoU 合并**：双掩膜会给出两个略有偏差的框（金框紧、彩色框带光晕），重叠 >0.5 合并成一个；
4. **光效判定换指标**：从「色相 bin 有几个」改成「**非暖色像素占比 ≥0.35**」。
   旧指标会被抗锯齿骗（金卡边缘渐变也会铺满 6 个 bin，于是所有金卡都判成「彩」）。

   实测区分度：

   | 卡 | 非暖色占比 |
   |---|---|
   | 金卡（5 张样本） | 0.00 ~ 0.08 |
   | 彩卡（紫粉光） | 0.90 |

5. **卡会淡入淡出**：同一场训练里 4 个技能帧分别读到 2/1/0/0 张。所以
   `_do_training_core` 在**进页面那一帧**先拍一次「器材基线」，某个技能的采样帧没卡时用基线补，
   不再把「这一帧没卡」当成「这场没带器材」。

### 2.4 验证（全量 397 张真实审计帧）

| 帧内张数 | 修复前 | 修复后 |
|---|---|---|
| 0 张 | 258（几乎全部，含真有卡的帧） | 192（真的没卡 / 卡已淡出） |
| 1 张 | 2 | 129 |
| 2 张 | 2 | 60 |
| 3 张 | 1 | 16 |
| ≥4 张（误检红线） | 4 | **0** |

光效判定：291 张金 / 6 张彩（彩卡确为稀有），抽帧目视核对 6 张全部正确。

`tools/test_equip.py` 重写为**人工标注回归**（原来喂的 `screenshots/sweep/` 已不存在，
那套断言是空转，等于从来没测过）：

## 3 框架能力：这次用了什么、为什么有几处没用

玩家要求「能用框架的都用框架」。逐项交代：

| 环节 | 框架能力 | 用了吗 |
|---|---|---|
| 判页 | `find_feature`（COCO 模板匹配） | ✅ 一直在用；本轮新增**采样期救帧**：文字判据全灭时，用「训练核心」4 套「决定」锚点做像素确认（`_anchor_page(f, only="训练核心")`），省掉 8 页全遍历 |
| 点击 | `click_box` / `click_box_if_name_match` | ✅ 用 |
| OCR | `self.ocr(frame=)` → `Box` | ✅ 用 |
| 取帧 | `self._frame()` + 框架 capture | ✅ 用 |
| **找卡片矩形** | `util/color.find_color_rectangles` | ❌ **不适用**。它假设目标是**纯色矩形块**（内部填充率 ≥`threshold`，默认 0.95，按钮那种）。器材卡内部是插画，只有一圈 4~6px 发光边框，填充率 0.08~0.5 且随插画变化，套用会漏检。需要「掩膜 + 闭运算 + 轮廓」这条链路，属于框架没覆盖的部分 |
| 找卡片颜色 | `get_mask_in_color_range` / `color_range_to_bound` | 可用但价值不大（只是把阈值转成 bound，`inRange` 还是自己调一次），暂留自写 `_gold_mask` |

采样期救帧的收益（跑起来能直接看到）：日志 `采样 0 帧有效` 与摘要新增的
「锚点层…采样救回 N 帧」。离线无法复现浮层遮挡，实跑一轮即可验证。

## 5 默认选中项：进页面就能采，一次都不点（玩家 2026-11-24 11:55）

玩家原话：
> 进入的时候默认就是投射的，不用点击直接就能采样，如果这时候要去点击它，会直接变成选中。

所以训练核心页的采样顺序被彻底改成「默认项优先、且只读不点」：

| 顺序 | 动作 | 说明 |
|---|---|---|
| ① | 找默认选中项 | `_selected_skill` 从深蓝高亮胶囊认出（浅蓝底/橙底两套皮肤都认；认不出返回 None） |
| ② | **先采它，全程不点击** | `_core_measure(..., how="default")`；采不到只重新取帧（`warmup=0.6` 重采一次），绝不补点 |
| ③ | 再逐个点开其余五个技能 | 有角标的排前面；为什么不再按角标筛，见 §6 |

三个要点：

1. **为什么要先采**：旧实现虽然也判断了 `name == selected` 就不点，但采样顺序按胶囊 `cy` 从上往下。
   一旦排在前面的技能先被点开，画面就成了那个技能的编队，轮到默认项时"采当前帧"采到的是别人的
   数据。W2D4「带经理加成 + 器材」的投射掉出候选池，根子就是这个顺序问题，不是"没有角标"。
2. **默认项不要求有角标**：它的编队一进页面就摊在画面上，采集成本是 0 次点击、仅几帧 OCR，
   属白捡的数据 → 从全部技能行（`rows`）里找，不限于带角标的 `targets`；六个技能都没角标时
   也照样采它。
3. **认不出高亮时**：六项一律点开采样（不特殊对待投射），靠排名选；收尾因为无法假定谁已选中，
   会点一次最优项再点「决定」。

证据侧：默认项的采样图落在 `core0_<技能>`（其余是 `core1_` 起），`DECIDE.txt` 里写明
「先进页面直接采默认帧、全程未点击」，采样失败则写「未采到，未参与排名」。
回归：`test_default_skill` 42 项，含「第一个动作必须是采默认项」「默认项一次都没被点」
「无角标仍采」「采样失败只重采不补点」四类断言。

## 6 候选池扩到六个技能（2026-11-24 第三轮实跑复盘）

第三轮实跑（`logs/run_1204.out`，12:04–12:41，约 950 步 / 3 个赛季）：

| 指标 | 结果 |
|---|---|
| 最终评分 | **8272**（目标 9000，差 728） |
| 训练核心页 | 70 步（同一次训练会连续多步停在该页，实际训练约 105 次） |
| 完整编队比较 | **只有 27 场**写出了「编队排名」 |
| 「没有角标，跳过」 | **205 次**（平均每场近 3 项被跳过） |
| 训练失败 | 3 次 |

三条实锤证据（都指向同一个根因：候选池太小）：

1. **只剩一个候选还被练了**：`投射 MAX 失败率 77%` 那场，其余五项全因"没角标"被跳过，
   排名里只有它一项 → 硬着头皮练了，几乎必然失败。
2. **「体能 1.00 分」单独成一场**：同一场里没角标的「意识」平时能到 5 分，却根本没采。
3. **平均每场只有 3 个候选**：角标只代表"今天这项有加成"，与编队里站几个人毫无关系，
   而得分主要来自队友 + 器材 → 用角标筛候选等于把好编队筛掉。

改法（`_do_training_core`）：

| 项 | 旧 | 新 |
|---|---|---|
| 候选池 | 只有带角标的（平均 3 项） | **全部六个技能** |
| 点击顺序 | 按胶囊 cy 从上往下 | **有角标的排前面**（中途被切页时预算已花在有加成的项上） |
| 默认项 | 有角标才采 | 永远先采、永不点击（见 §5） |

代价：每场多 3 次点击 + 3 段采样 ≈ +5 秒，一轮约 105 次训练 → **多 8~10 分钟**。
换掉的是"候选池太小被迫选差项"这个最大失分点，值得。

回归同步：`test_default_skill` 42 项（新增「无角标也全采」「有角标排前面」），
`test_goal` / `test_core` / `test_stability`(98) / `test_pages_real`(50) 全绿。

**未验证**：这轮改动还没实跑到评分页 —— 一进游戏就停在「选择器材」第 5 槽为空，
`auto_fill_equip: false` 按玩家要求暂停 + 弹窗，等人补槽。下一轮从这里接着跑即可。
