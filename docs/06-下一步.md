## P0 · 两个非阻断但影响质量的问题

### P0-1 比赛结算页还在走「未知页」兜底（低成本，先做这个）

**现象**：155 条 WARNING 里 114 条是 `未知页面（第 N 次），点屏幕中间推进`，占 73%。

**这一屏的实际文本**（日志原样）：

```
['战胜伊澄综合学园', '获得奖励', '全属性+7', '点击屏幕继续']
```

兜底「点屏幕中间」能推进，但每屏空转 2~4 步，一轮白烧 100+ 步。

**怎么做**：在 `_classify` 里加一个 `比赛结果` 页面类型，指纹用
`has("获得奖励") and has("点击屏幕继续")`（`战胜XX学园` 的学园名会变，不能写死），
优先级放在「未知」之前。处理函数点「点击屏幕继续」或屏幕中部。

**验收**：同一轮里 `未知页面` 条数从 114 掉到个位数。

### P0-2 编队采样时序 —— 真正影响打分质量的那个

**现象**：48 次采样里 **23 次一帧可用都没拿到**（`编队采样 0/6 帧可用`），
12 次整体失败退回默认项（`全部技能采样都失败，按当前默认项决定`），
排名里出现 8 次 `队友0`。等于**一半的编队打分实际上没执行**。

**根因**：点开技能徽章后，编队面板会盖住右侧技能列，`looks_core` 判定失败 → 整帧丢弃。

**为什么现在不改等待时间**：这不是「等短了」，是筛选标准用错了 ——
拿「这页还像不像训练核心」当帧有效性判据，面板一盖住就必然判失败。

**正解（按框架官方建议，按钮/角标用模板或颜色，别用 OCR）**：
1. 用 `get_skill("generate-templates")` 的流程，给六项技能的角标/等级图标做命名特征，
   全屏截图 + COCO 标注存 `ok_templates`，`generate_templates` 导出；
2. 采样式改成「点开徽章 → 固定等一个动画周期 → 抓帧 → 用 `find_feature` 定位，
   不看页面分类」；
3. 拿不到角标时**明确记为缺失**，不要退回「默认项」假装完成（现在日志里两者长得像）。

**验收**：连续 3 轮 `编队采样 0/6` 次数为 0，排名里不再出现 `队友0`。
