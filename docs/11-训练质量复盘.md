## 2 那到底差在哪：训练次数

| 周 | 训练天数 | 出行天数 | 没训练的工作日 |

| 第 2 周 | 周一~周六 **5 天**（周2~周6） | 周日 1 天 | 无 |

**结论：每周少练 1~2 天，都发生在周六。**

根因是一条任务参数：`训练精力下限 = 40`。

第 4 周实测精力轨迹：

```
星期2 102 → 星期3 72 → 星期4 62 → 星期4 训练后 17 → 星期5 32
```

星期六开局精力 **32 < 40** → 直接判「精力不够，去出行」，于是周六整天没练。
但同一周星期5 精力只有 17~32，照样进训练项页把训练做完了 —— 说明**32 完全够训练**，
是阈值设太高把自己挡住了。

每次训练的实际消耗（日志推算）：**约 15~25 点精力**，一周 6 天共约 120 点，上限 130 完全够。
所以「周一到周六全训练」本来就能做到，是门槛和精力规划没算对。

## 6 按你的口径改了什么（2026-11-23 本轮）

| 规则 | 改法 | 位置 |
|---|---|---|
| **周一到周六全训练** | `训练精力下限` 40 → **12**；精力 32 的周六不再被挡成出行 | `configs/AutoTask.json` |
| **从不失败** | 新增 `fail_limit: 0`：有 0% 的技能就**硬性排除** >0% 的；全高才退回原排名 | `strategy.yaml` + `_apply_fail_limit()` |
| **意识不耗精力、低精力时加权** | 新增 `consciousness`：精力 < 45 时给「意识」+99，直接拉第一 | `strategy.yaml` + `_apply_consciousness_boost()` |
| **物品购买** | 每日页接上商店入口（精力 < 50 才进，一天一次）；`商店自动购买` 改 true | `_do_daily()` + `_want_shop()` |

### 精力规划（设计口径）

```
周日      不训练 → 出行「公园」把精力补回 130（为下周 6 练做准备）
周一~周六  每天训练 1 次（约 -20 精力）
  精力 ≥ 45  正常按「队友 + 器材」打分选
  精力 < 45  意识加权拉满（不耗精力、小幅回精力、成功率最高）
  精力 < 12  才去出行/休息（真练不动了）
精力 < 50 且当天还没进店 → 进店买精力药（有就买，最多 2 次）
```

按这个账：130 精力 ÷ 6 天 ≈ 每天 21 点，正好覆盖周一到周六；
中途任何一天精力掉到 45 以下，意识顶上去把精力拉回来，**不需要额外出行**。

## 7. 第二轮修正（2026-11-23 11:40，玩家当面定的三条）

| 你的原话 | 最终实现 |
|---|---|
| 「失败可以赌一把，收益如果很高，小于 30 都能去」 | `fail_limit: 30`：30% 以内不排除，按 `收益 × (1−失败率)` 排期望。4 队友 ×25% 失败 = 3.0 分，仍然赢过「2 队友 0 失败 = 2.0 分」→ 会主动赌。选中带失败率的项会打一条「赌一把」日志 |
| 「商店具体的效果你去 wiki 看看，决定可以买哪些、长什么样」 | 查了训练流攻略 + 实机截图 OCR，定出 7 类白名单（0 元馈赠 / 特训牛奶 / 精力饮料 / 器材暴击 / 教科书 / 属性秘籍 / 护符），带价格上限；详见 `docs/12-商店采购清单.md` |
| 「周日的休息指的就是去公园」 | 确认现状即此。顺手修了公园子页兜底顺序：读不到数值时 `野餐 > 划船 > 散步`（原来会按地点顺序挑到补得最少的散步） |

顺带修的两个隐藏问题：

1. **价格一直读不到**：游戏里价格是**纯数字**（130 / 40 / 50），不带「元」字，
   而代码只认 `\d+元` → 价格上限从来没生效过。现在两种都认。
2. **进店时机太窄**：原来只在精力 <50 时进店，可商店是「7 天刷新」——
   特训牛奶、金秘籍这些一周才出现一次，错过就没了。现在换周也例行进一次。
