## 2 先回答你问的两件事

### 2.1 窗口大小变化有影响吗

| 项 | 结论 |
|---|---|
| 画面比例 | 框架会按 16:9 裁切，**不会**因为拖成任意比例就读歪 |
| 相对坐标（点击位置、ROI） | 安全，全部按 `cx/w`、`cy/h` 比例算 |
| 绝对像素阈值 | **原来不安全**（角标检测写了 16~52px），本轮已改成按 1920x1080 折算的比例 |
| 最小尺寸 | 低于 1280x720 框架会自己 resize；非 16:9 也会 resize 到支持列表里的一档 |
| 建议 | 固定 **1920x1080 窗口化**最稳；改了大小也能跑，但所有阈值都是在 1920x1080 下标的定 |

### 2.2 窗口不在前台有影响吗

分两条链路，结论完全不同：

| 链路 | 实现 | 不在前台会怎样 |
|---|---|---|
| **截图** | `BitBlt_RenderFull`（PrintWindow） | **没影响**。被别的窗口挡住照样抓得到 |
| **点击** | `Pynput`（真实鼠标事件） | **点击被静默丢弃**。框架 `clickable()` 判的就是「是否前台」，不在前台只打一行 info 不报错 |
| 最小化 / 拖出屏幕 | 框架 `pos_valid` 检测 | 自动 `pause` 并发通知，不会乱点 |

⚠️ 所以最坑的情况是「窗口被别的程序盖住但没最小化」：画面照抓、日志照走、**点击全丢**，看起来像卡死。

本轮已加 `_ensure_foreground()`：每步检查，不在前台就抢回来（限频 3 秒一次）。
