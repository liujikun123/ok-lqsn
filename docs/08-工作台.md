# 08 · 工作台（发布后给人用的界面）

> 这份文档对应 `workbench/` 目录。
> 跟 `ok gui` 的区别：`ok gui` 是**开发调试台**（能改任务、看识别框、连 MCP）；
> 工作台是**发布后的使用端**，只给「打开就能用」的人看，不暴露内部机制。

---

## 怎么跑

```bat
run_workbench.bat          :: 推荐，自动用 ok-bsg 的虚拟环境
:: 或者
..\ok-bsg\.venv\Scripts\python.exe -m workbench
```

窗口要求：Windows、装了 PySide6（虚拟环境里已装 6.12.0）。
不需要游戏先开着 —— 工作台自己会把游戏拉起来。

---

## 这一版能干什么（框架）

| 能力 | 说明 |
|---|---|
| 加载配置 | 下拉选 `config/*.yaml`（只有带 `tuning` 段的才列出来），右侧显示摘要表 + 原文预览，可一键用系统默认程序打开 |
| 环境自检 | Python / PySide6 / ok 框架 / 游戏本体 / 启动器 / 规则文件，六项逐个给通过或失败原因 |
| 状态监视 | 每 3 秒刷新：游戏进程在不在跑、游戏窗口在不在（有进程没窗口时也能看出来是卡在启动器） |
| 三个启动动作 | ①只启动游戏 ②启动游戏并训练 ③只跑训练（游戏已开） |
| 实时日志 | 子进程输出按行刷进界面，ERROR 红、WARNING 橙；可隐藏 onnxocr 的碎碎念；可存成文件 |
| 停止 | 整棵进程树一起杀（`taskkill /T /F`），不会留下半个 ok 进程抱鼠标 |

底部按钮的语义要分清：

```
启动游戏            tools/start_game.py            只到大厅，不动训练
启动游戏并训练      tools/start_game.py --auto     到大厅后自动接 AutoTask
只跑训练            python -m ok run_task ...      假定游戏已经在大厅
```

## 文件职责

```
workbench/
├─ __init__.py     说明（写在这里，免得以后忘了当初为什么另起一套 UI）
├─ __main__.py     python -m workbench 的入口
├─ runner.py       非界面部分：读配置 / 环境自检 / 进程管理
└─ app.py          纯界面：布局、样式、按钮接线
run_workbench.bat  双击启动
config/workbench.yaml  工作台自己的配置（游戏路径、任务名、超时）
```

`runner.py` 对外只暴露四样东西，界面层不碰业务：

- `load_workbench_cfg()` / `list_rule_files()` / `summarize_rule()`
- `preflight()` → 自检条目
- `game_running()` / `game_window()` → 进程与窗口
- `Runner`（QObject）：`run(args, label)` / `stop()`，信号 `log / state / done`

## 配置

`config/workbench.yaml`：

```yaml
game:
  launcher: 'D:\LQSN\launcher.exe'                 # 必须由它点「启动游戏」
  exe: 'D:\LQSN\games\LQSN\k3_windows_ob.exe'
  process: k3_windows_ob.exe                       # 判断「在不在跑」用的进程名
  window_keyword: k3_windows                       # 找窗口用的进程名关键字
  boot_timeout: 150                                # 进大厅超时（秒）
task:
  config: 'src.config:config'                      # ok 框架的配置导入路径
  name: AutoTask
  default_rule: config/strategy.yaml
run:
  log_dir: logs
```

换电脑/换安装目录只改这里，不动代码。

## 后续要加的东西（按优先级）

1. **规则可视化编辑**：现在摘要表只读。下一步让「主训角色 / 空槽处理 / 炒股模式」
   这些高频项能在界面直接改，保存时只回写 yaml 对应几行（不要整份重写，注释会丢）。
2. **打包成 exe**：`pyinstaller --noconsole --add-data`，把 `assets/`、`i18n/`、`config/`
   一起打进去。注意 onnxocr 的模型目录必须显式带上，否则运行时才报错。
3. **多套配置档**：不同主训角色 = 不同 `strategy.yaml`，做成「方案」列表（名字 + 规则文件）。
4. **异常重试**：现在任何一步失败都要人点。至少加「训练中断 → 自动点继续训练 → 重跑」。
5. **通知**：`log_error(notify=True)` 目前走框架自带通道，工作台里应该也弹一条
   系统托盘气泡，人不在电脑前也能知道停了。
6. **日志/截图清理**：`logs/` 和 `screenshots/` 只增不减，加个「只保留最近 N 天」。
7. **托盘常驻 + 定时开跑**：每天固定时间自动训练一轮。

## 已知限制

- 工作台不代替 `start_game.py`：启动器那一步（点「启动游戏」、关公告、点「点击进入」）
  仍由脚本做，工作台只是调用它。所以游戏路径不对时，报错会出现在日志区而不是按钮上。
- 同一时间只允许跑一条命令（两个脚本同时抢鼠标会互相踩）。
- 关闭窗口会连带停掉正在跑的任务（会先问一次）。
