# 00 项目规划

## 1. 背景

- 游戏：《篮球少女：飞跃巅峰》PC 版，原生 Windows 客户端（进程 `k3_windows_ob.exe`，窗口类 `UnityWndClass`，1920×1080）。
- 玩法：每天（游戏内星期）做行动（训练 / 休息 / 商店 / 周末出行 / 比赛），**点一次「训练」= 一个完整剧本，约 7 个「周」× 7 天**，中途不回大厅，
  最后「训练评分 → 恭喜获得 → 训练结束」才回大厅。全程要连续推进几十屏。
- 手工玩一轮约 20 分钟（录制实测 21 分钟、963 帧、422 次点击），重复度高，适合自动化。

## 2. 目标

> **做一个「看一眼屏幕就知道现在在哪、下一步能点哪些、该点哪个」的自动训练器，规则全部可配置。**

拆成四件事：

| # | 目标 | 说明 |
|---|---|---|
| G1 | **状态识别** | 任意时刻知道自己在哪个页面（状态机节点），认不出必须停，不许瞎点 |
| G2 | **可用动作** | 每个页面知道有哪些按钮可点、点完会去哪（状态机的边） |
| G3 | **决策规则** | 选哪个按钮由玩家规则决定，规则写在 `config/strategy.yaml`，改配置不改代码 |
| G4 | **可回溯** | 每步都有日志（认成什么页、看到什么字、为什么选它、点了哪），出错能复盘 |

## 3. 范围

**做**
- 自动跑完整训练（一周 → 一个剧本 → 回大厅）
- 页面识别 + 状态机推进
- 训练核心的编队打分（队友/器材/金光彩光）
- 随机事件、商店、出行、扭蛋、加强训练、比赛（跳过）、剧情跳过
- 只读体检 / 单步执行 / 录制分析等调参工具

**暂不做**
- 多开、代理、改内存、跳过动画加速（只做正常点击）
- 账号体系 / 云同步 / 打包分发（先在本机跑通）
- 比赛手动打（按玩家规则一律「跳过比赛」）
- 自动配置阵容/笔记/器材（玩家明确说过：这些他手工配好，脚本不要动）

## 4. 形态：为什么是状态机

游戏是典型的**有限状态机**：页面 = 状态，按钮 = 迁移，同一个按钮在不同状态含义不同
（例：「决定」在训练核心是开训，在加强训练页是确认档位）。

所以项目不写成「一条点击序列」，而是：

```
循环 {
  截图 → OCR/图像特征 → 匹配状态（anchors）→ 命中唯一状态
    → 取该状态的候选动作 → 用规则打分 → 执行 → 等页面变化 → 再判状态
}
```

状态定义放 `config/states.yaml`（设计稿），规则放 `config/strategy.yaml`（已在用）。
细节见 `docs/01-架构设计.md`。

## 6. 硬约束（技术事实，不可绕过）

| 约束 | 事实 | 后果 |
|---|---|---|
| 截图 | WGC 后台截图：被遮挡能抓，**最小化抓不到**（窗口矩形 −32000） | 运行时窗口不能最小化 |
| 点击 | 该 Unity 客户端对 PostMessage 无响应 | 只能用 Pynput 真实鼠标 → **窗口必须前台**，且别动鼠标 |
| 分辨率 | 按 16:9 缩放，基准 1920×1080 | 换分辨率要重标坐标 |
| OCR | PP-OCRv6，小字/艺术字会错（「残」识别成「葉」之类） | 关键判定不能只靠单字 OCR，要配图像特征 |

## 7. 风险

| 风险 | 影响 | 对策 |
|---|---|---|
| 页面锚点靠文字，艺术字认不出 | 卡在未知页 | 图像特征兜底（卡片/胶囊/按钮形状颜色），锚点宁多勿少 |
| 兜底逻辑太主动 | 乱点进小游戏/多进一次出行页（已发生两次） | 默认「认不出就停」，兜底必须显式开关 |
| 游戏更新改 UI | 全部坐标失效 | 坐标与指纹集中配置，改一处即可 |
| OCR 抖动（同屏数字跳变） | 误判体力/天数 | `strategy.yaml` 的 `value_jump_limit` 做跳变过滤 |
| 玩家规则只覆盖已见过的情形 | 遇新事件只能兜底 | 兜底规则明确写「选第一个」并记日志，事后补规则 |

## 8. 成功标准

1. 点一次「训练」，脚本能自己跑完整个剧本回到大厅，中途不卡。
2. 卡住时**自己停下并说明卡在哪一页、屏幕上有什么字**，而不是乱点。
3. 想改行为（比如「笔记优先」改成「公园优先」）只改 `strategy.yaml` 一行，不动代码。
