| 5 | 手工维护 `assets/templates/x_close.png` 单张模板 | `assets/templates/` | 锚点库统一管理 | 模板不再是散装文件 |

新增的两个文件：

- `tools/build_anchors.py`：**用 OCR 离线裁锚点**（OCR 只在建库时用一次），
  产出 `assets/coco_annotations.json`（框架吃这个格式）+ `assets/anchors.json`（页面→锚点、锚点→搜索区域）。
- `tools/test_anchors.py`：锚点库自洽性 + 判页融合 + 硬约束 + 推进器底层件的回归测试（30 项全过）。

### 用锚点认页 vs 原来用关键词认页

```
OCR 关键词（73 个 if 分支）   →  说出「这是什么页」，读花就崩
框架锚点（像素裁片匹配）      →  认「这页长什么样」，不读字也能认
转移硬约束（PAGE_FORBIDDEN）  →  否决「物理上不可能出现的页」
```

`_classify` 现在是：`OCR 结果 → 硬约束否决 → 锚点匹配 → 融合（冲突时信锚点）`。
锚点只查 `assets/anchors.json` 里登记过的页面，没登记的页仍走 OCR + 通用推进器。

当前锚点覆盖（`tools/build_anchors.py` 的 SPEC，加一行就能扩）：

| 页面 | 锚点 | 命中要求 | 实测分数 |
|---|---|---|---|
| 训练项页 | `训练项页_决定` | 1/1 | 0.82+ |
| 商店 | `商店_标题` / `商店_关闭` | 1/2 | 0.99 / 1.00 |
| 训练评分 | `训练评分_标题` / `训练评分_继续` | 1/2 | 1.00 / 1.00 |

**踩到的框架硬约束**：`read_from_json` 要求「一个类别 = 一个框」，同名两个框直接
`ValueError: Multiple boxes found`，所以一个锚点只存一张原型，另外用「搜索区域」覆盖
该按钮在不同位置的变体（如训练项页的六个训练项页，决定按钮 y 从 317 变到 714）。

**锚点素材必须是实际出帧分辨率**（框架 `resize_to` 后是 1600×900）：
一开始混进了 1920×1080 的老截图，模板尺度对不上，匹配分数只有 0.2~0.3 全灭；
只收 1600×900 后立刻 0.82~1.00。

**数值会变的文字不能当锚点**：试过用「失败率0%」当锚点，跨截图匹配失败——
0%/5%/12% 像素完全不同。锚点只能选「字形+底纹固定」的元素（按钮、标题、图标）。

## 三、确认「框架不如我们」而保留的（附理由）

| 保留项 | 位置 | 框架对应 | 为什么不用框架的 |
|---|---|---|---|
| `_ensure_foreground` | `AutoTask.py` | `ensure_in_front()` | 框架只调 `hwnd.bring_to_front()`，失败只 warning；我们用 AttachThreadInput + SetForegroundWindow 真抢前台。向日葵远程会反复抢焦点，**框架版会导致 Pynput 点击被静默丢弃**（日志在走、游戏不动） |
| `_frame(timeout=5)` | `AutoTask.py` | `next_frame()` | 框架 `next_frame()` 在窗口最小化/显示器断电时**永久阻塞**；我们加可见性预判 + 超时 + 看门狗 |
| `_frame_diff` | `AutoTask.py`（6 行） | 无 | 框架没有「两帧差多少」的接口，推进器判断「点击有没有生效」要用 |
| `_looks_transient` / `_is_loading_frame` | `AutoTask.py` | `is_blank` / `is_pure_black` | 框架只有「是不是纯黑/空白」，我们的判据是业务语义（HUD 在不在、字数够不够、蓝色剪影占比） |
| `_shot` / `_audit_path` | `AutoTask.py` | `screenshot(name)` | 框架的 `screenshot()` 是发 GUI 信号，不负责按「周/星期」建目录落盘留证 |
| `_read_stamina` / `_read_gold` | `AutoTask.py` | 无 | 业务数值解析（局内精力 vs 局外专注的歧义消解） |

## 四、2026-11-24 第二轮去重（本次做完的）

| 项 | 改法 | 效果 |
|---|---|---|
| `_find` / `_all` | 不再自己双重循环遍历，改调框架 **`find_box_by_name` / `find_boxes_by_name`**（子串匹配转成正则交给框架） | 少一份匹配实现；附带得到「词的先后顺序 = 优先级」这个更合理的语义（`["取消","关闭"]` 优先取消） |
| `_click_item` | 改调框架 **`click_box(box)`**（内部会回到我们重写的 `self.click`，遮挡检测/置顶点击照样生效） | 框内相对坐标不再自己算 |
| `_texts` | 保留 dict 投影（`t/cx/cy/b`），但**只做投影**，不含任何算法 | 5000 行调用点不用改；定位是「框架 Box 的一层薄视图」 |
| `tools/survey.py` | 重写成「命令行 + 打印」，窗口/抓屏/点击/OCR 全部改调 `tools/devkit.py` | 124 行 → 约 60 行，且抓的是**客户区 1600×900**，和框架帧同坐标系 |
| `tools/start_game.py` | `Vision` 的 OCR 引擎与解析改调 `devkit.engine()` / `devkit.ocr_rows()` | 顺手修掉一个真 bug：它原来只传 `use_openvino=True`、**没传 `use_npu=True`**，和实跑用的不是同一个后端 |
| `tools/devkit.py`（新） | 窗口/抓屏/点击/OCR 的唯一实现，能复用的地方用框架 `ok.util.window.find_hwnd / get_window_bounds` | survey / start_game / build_anchors 三份重复合成一份 |

> 为什么 `_texts` 不彻底换成 `Box` 对象：101 处 `it["t"]`、51 处 `it["cx"]`，
> 外加 10 多个测试文件手工构造 `{"t":..,"cx":..}`。收益（少一层 4 行投影）
> 明显小于风险，所以只把**算法**部分交回框架，投影层保留并在代码里写明。
