| 项 | 值 |

| 时长 | 约 21 分钟 |

| 覆盖 | 第 1 周 ~ 第 7 周完整一段训练（大厅 → 训练 → … → 训练结束） |
| 文件 | `timeline.json`（全部 OCR 结果 + 点击坐标）、`summary.md`、`outline.md`、`digest.md` |

### timeline.json 结构

```json
{
  "events": [
    {"i": 5, "t": 7.12, "kind": "click", "img": "frames/005.png",
     "texts": [["训练剧本", 154, 50, 170, 47], ...],
     "click": {"x": 1639, "y": 943, "rx": 0.854, "ry": 0.873}}
  ]
}
```

- `texts` 每项 = `[文字, x, y, 宽, 高]`，坐标是**窗口内**像素（1920×1080）
- `click.x/y` 是**桌面**坐标（窗口有偏移时不能直接用）；`click.rx/ry` 是窗口内归一化坐标 —— **对齐必须用 rx/ry**
- `kind` 只有 `screen`（纯截图 OCR）和 `click`（点击时那一屏的 OCR）

## 5. 怎么重新分析素材

```bat
:: 1) 还原「哪一屏点了哪个按钮」
.venv\Scripts\python.exe tools\trace_flow.py > demo\flow.txt

:: 2) 卡片识别回归（不依赖游戏在跑）
.venv\Scripts\python.exe tools\detect_cards.py ..\ok-bsg\demo\session_1122_200929\frames\493.png

:: 3) 事件卡识别回归
.venv\Scripts\python.exe tools\test_event_cards.py
```

## 6. 环境重建（换了机器怎么办）

1. 装 Python 3.12（本项目用 `C:\Users\Administrator\py312`，版本必须 3.12，ok-script 要求 `>=3.12,<3.13`）
2. 建虚拟环境 → 装依赖：
   ```bat
   python -m venv .venv
   .venv\Scripts\python.exe -m pip install "ok-script[adb,default,ocr,qt]==3.0.0b3" openvino opencv-python
   ```
3. 首次跑 OCR 会自动下载 PP-OCRv6 模型（需要联网，约几百 MB）
4. 确认 `src/config.py` 里 `windows.exe = ['k3_windows_ob.exe']`、`capture_method` 首选 `WGC`、`interaction` 首选 `Pynput`、**没有 adb 键**

现在这套环境可以直接复用：`../ok-bsg/.venv`（`requirements.txt` / `pyproject.toml` 已随项目复制）。

## 8. 用真实素材「教程序认页面」（2026-11-23）

页面识别不能靠拍脑袋加关键词 —— 要拿程序**实际读到的文字**当证据。这套流程已固化成工具，以后加新页面照做：

### 8.1 采集 / 勘察工具

| 工具 | 作用 |
|---|---|
| `tools/survey.py shot [tag]` | 截当前游戏画面到 `logs/survey_*.png` |
| `tools/survey.py click X Y` / `clickr rx ry` | 按比例/绝对坐标点一下（自动把游戏置前） |
| `tools/survey.py ocr` | 用**项目同款** onnxocr(openvino+npu) 读当前画面，打印每个词的文字+坐标 |

OCR 初始化必须 `use_npu=True, use_openvino=True`（与 `src/config.py` 一致）；传 False 会走 onnxruntime 后端，而这个 venv 没装它 → 报错。

### 8.2 素材从哪来（不用重跑游戏）

- `logs/pick_list/`、`logs/grid_list/`：选队友/选笔记/训练项页/选器材的真实截图（文件名是 GBK 乱码，但图像有效）
- `screenshots/auto/`：实跑每步自动截图（`core_fail` / `shop` / `done_hall` / `stuck_*`）
- `logs/ok-script.log`：最有价值 —— 每步都记了 `页面：X | 文字: [...]`。统计 `grep -oP '页面：\K[^ ]+' | sort | uniq -c` 能看出哪类页面识别最差
- 历史截图多而重复：用缩略图 MD5 去重（80 张 → 一堆独特画面），拼成 montage 一次总览

### 8.3 从素材到规则的闭环

1. 用 `survey.py ocr` 对每张素材截图跑 OCR，拿到**程序真实读数**（不是人眼看到的字）
2. 把读数固化成测试夹具 → `tools/test_pages_real.py`
3. 跑测试看哪些判错，再改 `_classify`；改完重跑，全套回归不退化才算数

### 8.4 这次靠真实素材抓到并修复的 4 个误判

| 真实现象 | 根因 | 修法 |
|---|---|---|
| 开训前「选择笔记」被判成「笔记学习」，去找「学习」按钮卡住 | 两页都有「契合度」，旧规则见契合度就判笔记学习 | 选人三连（选择队友/器材/笔记）的独占词判定提前到契合度之前 |
| 1104 次「未知页」大头是属性成长面板（只剩「倍率加成 心·技·体 へ」） | 旧规则要求 ≥3 个属性词，OCR 把属性行吞了就掉进未知 | `is_attr_panel` 命中即判训练结果，不强求属性词数量 |
| 「本周总结」被判成训练项页，对着不存在的训练项条目空转 | 六项技能在底部属性条，被 `right_skills>=4` 抢走 | 加独占词快车道（本周总结/球队评分、点击屏幕继续、属性面板）放在技能判定之前，并让本周总结复用「点击继续」处理 |
| 属性面板规则会吃掉开训前的「额外队友」选人页（14:20 卡死那张） | 「额外队友」既是选人页词、又在 `is_attr_panel` 词表里 | 属性面板判定加排除：有「筛选」开关或右侧≥2 张等级牌卡 = 选人页，优先判选择队友 |

**核心教训**：大厅里「训练项页 / 选择队友 / 选择笔记 / 选择器材」四页长得几乎一样（都有底部六属性条 + 右下黄色「下一步」），不能只靠一个"右侧黄色卡片"视觉信号。每页都有稳定独特词（见 8.4 与 `test_pages_real.py` 夹具），靠独占词 + 规则优先级 + 少量视觉兜底三者结合才稳。
