## 1 「32% 读数失败」是怎么来的（已证伪）

上一轮我把日志里的 `训练项读数 4/6 帧有效（试了 4 次）` 读成了「6 帧里丢了 2 帧」。
实际读代码就知道不是：

```python
if used >= min_frames and len(pcts) >= 2 and len(name_sets) >= min_frames:
    break          # min_frames 默认 4 —— 采够 4 帧就收工
```

`tries == used == 4`，说明**每一帧都通过了判据、第 4 帧提前收工**，没有废帧。

交叉验证：

| 证据 | 数值 |
|---|---|
| 日志 `训练项读数 4/6 帧有效` | 260 次（另 1 次 5/6），`试了 4 次` = 4 帧全用上 |
| 日志 `读数 0 帧有效` | **0 次** |
| 审计 `有效读数：True/False` | **397 / 397 全 True** |
| 摘要 `读数失败 N 项` | 全部 **0 项** |

也就是说：**技能级读数失败率 0%，帧级丢失 0 帧**。这个方向没有问题，不需要改。

## 2 真问题：器材（支援卡）识别一直全灭

### 2.1 现象

实跑日志 263 次读数，`器材 0` 出现 **258 次**（另 4 次读到 6 张、2 次读到 2 张，都是误检）。
而画面里明明每场都摆着 1~3 张卡（玩家原话：「中间一个器材（鞋子），不是很明显吗」）。

旧 `find_cards` 的 docstring 甚至把这件事当成正常现象写进去了：
「离线跑 122 帧：0 张 108、1 张 9、2 张 3、3 张 2」。

后果：`core_score.equipment`（普通 0.5 / 金光 1.0 / 彩光 1.5）**从来没被加进过排名**，
每场训练白丢 0.5~4.5 分 —— 这是 9000 分缺口的实打实来源之一。

### 2.2 根因

旧实现用「金色掩膜」找卡：

```python
mask = (r > 205) & (g > 155) & (b < 160) & ((r - b) > 45)
```

**木地板本身就是橙黄色**，整片地板都满足这个条件。实测单帧：

```
ROI 内 mask 覆盖率 32.41%
最大连通域 639x167（= 整个 ROI 宽度）
```

卡片和地板连成一大块，被「最大宽度 0.14w」的尺寸过滤直接丢掉 → 0 张。

### 2.3 修法（`src/core/cards.py` 重写）

1. **双掩膜**：`金边（b<105 把地板分出去）` ∪ `高饱和色块（彩光卡用）`；
2. **形态学核随分辨率缩放**（1600 宽 → 13，1920 宽 → 17）；
3. **IoU 合并**：双掩膜会给出两个略有偏差的框（金框紧、彩色框带光晕），重叠 >0.5 合并成一个；
4. **光效判定换指标**：从「色相 bin 有几个」改成「**非暖色像素占比 ≥0.35**」。
   旧指标会被抗锯齿骗（金卡边缘渐变也会铺满 6 个 bin，于是所有金卡都判成「彩」）。

   实测区分度：

   | 卡 | 非暖色占比 |
   |---|---|
   | 金卡（5 张样本） | 0.00 ~ 0.08 |
   | 彩卡（紫粉光） | 0.90 |

5. **卡会淡入淡出**：同一场训练里 4 个训练项帧分别读到 2/1/0/0 张。所以
   `_do_training_core` 在**进页面那一帧**先拍一次「器材基线」，某个训练项的读数帧没卡时用基线补，
   不再把「这一帧没卡」当成「这场没带器材」。

### 2.5 2026-11-26 补充：器材不走 OCR；按训练项分布；品质三档已校准

**玩家**：「你读器材是靠 OCR 不是靠图像的吗？器材上面没有文字啊。」

对，**不走 OCR**（也从来没用过）。卡面只有插画/图标（球、护腕、人物…），
玩家看到的「像个字」其实是图标轮廓，没有可读文本 —— 所以
`find_cards` 只用「金边掩膜 ∪ 高饱和掩膜 + 闭运算 + 轮廓尺寸/长宽比/致密度」，
`card_quality` 只用「框线那一圈的颜色」。产出只有两个量：**几张**、**此刻是否在暴击**（普/金/彩）。

四条更正（都是玩家 2026-11-26 当面纠正的）：

1. **按训练项分布，不是场级固定**
   玩家：「器材是开局先选好五个，训练过程中这些器材可能分布在各个不同的训练项目里，
   也有可能不出现，所以不是固定的；上限也不是三个，四五个也可能。」
   → 按项计分；`MAX_CARDS = 5`；ROI 右边界 0.63 → 0.66。

2. **品质分三档，采样点决定成败**（见 `docs/04` #73）
   玩家先纠正「普最多、金次之、彩最少」，后给手机截图「左边普通、右边金光」。
   关键在于采样圈位置：

   ```
   bbox 边界
   内缩 1~3px  ── 框线本身（普 S≈125 / 金 S≈210）   ★ 必须取这里
   内缩 2~6px  ── 卡面底色（**所有卡都橙黄，S≈170**） ← 取这里就只剩单峰
   ```

   826 张实机卡实测：

   | 框线最外沿 S | 数量 | 判定 |
   |---|---|---|
   | 120~165 | 519 | 普（浅黄细框） |
   | 165~208 | **0** | 空档，阈值 185 落这里 |
   | 209~225 | 296 | 金（浓橙粗框 + 外光晕） |
   | 多圈 rainbow≥0.30 且 warm≥0.05 且 nbig≥3 | 11 | 彩（彩虹光晕） |

   比例 62.9% / 35.8% / 1.3%，与玩家「普最多、金次之、彩最少」吻合。

3. **采样不能取框外**
   先试过 bbox 外侧 2~6px，13 张判彩里 7 张是假的 —— 那些卡在室外球场，
   框外是蓝地板/绿草地，暖色占比直接掉到 0.00，金卡也判彩（全是 `item0_Shoot` 帧）。

4. **「彩」的假阳性**
   「+33 / +36」火焰伤害数字轮廓致密度 0.55~0.62（真卡 0.88~0.94、
   彩卡 0.69~0.71）→ `MIN_EXTENT = 0.66` 滤掉。

5. **彩卡判据要抗背景**（见 `docs/04` #74，玩家第四次纠正）
   玩家：「彩色实际是长这样的」（彩虹光晕），「背景也有可能会变，
   除了黄色背景还会这种蓝色的，你要测试一下这两种都能区分出来。」
   只看「青蓝紫占比」会被蓝色球场打爆 —— 纯蓝地板占比 1.00、纯蓝天 0.96~1.00，
   比彩卡还高。改成 **rainbow≥0.30 且 warm≥0.05 且 nbig≥3**（多色相 + 冷暖共存）。

   | 来源 | rainbow | warm | nbig |
   |---|---|---|---|
   | 彩卡（黄 / 蓝背景） | 0.66~0.90 / 0.66~0.81 | 0.08~0.15 / 0.06~0.30 | 4~7 / 3~6 |
   | 纯蓝地板 / 纯蓝天 | 1.00 / 0.96~1.00 | **0.00** | **1** |
   | 金卡 / 普卡 | 0.00 / ≤0.09 | 0.98 / 0.93~1.00 | 1 / 1~2 |

   采样位置也和金不同：**彩要扫 bbox 内 0.8%~11% 的 9 圈取最浓的一圈**
   （光晕有厚度，bbox 被撑大时最外沿读不到彩虹：玩家截图那张篮球架卡最外沿 0.21、
   扫到 7px 才 0.79）；金仍只能在最外沿读，多圈取 max 会让普卡飙到 244（撞亮黄内框）。

6. **彩卡会被致密度 0.66 整张滤掉**
   玩家截图那张篮球架彩卡 `extent=0.41`，原来直接漏检（黄背景图只检出 1 张，应为 2 张）。
   现在 `extent ∈ [0.35, 0.66)` 时，若有**强彩签名**（rainbow≥0.55 且多色相且冷暖共存）则收下；
   右侧训练项按钮/笔记页商品卡 rainbow ≤0.48，挡得住。

7. **MAX 标记不能当判据**
   玩家：「Max 不是一定有的，不能只凭 Max 来看。」
   实测 24 张普卡里 2 张带 MAX、11 张彩卡里也有不带 MAX 的 —— 互不蕴含。

8. **金 / 彩 是局内暴击状态，不能按项比较**（`docs/04` #75）
   玩家定论：「随着训练，在局内它这个器材的熟练度会提升，就会有几率变成金色和
   彩色的暴击效果。」所以三档读的是「这一刻有没有暴击」，是随机、随时间闪的事件：
   同一件器材 20 秒内实测 金→普→普→普普金→普；同一件器材既会以普框出现，也会以
   金/彩 框出现（11 张彩卡对应 5 种图标、24 张普卡只有 4 种图标）。

   后果有两个，必须写死在这里：
   - 单帧档位**不能代表训练项的价值**（只是随机事件的一次抽样）。
   - 5 个训练项是**依次**采的，熟练度一路上涨，按档位计分 = 给「最后采的那项」
     白送 0.5~1.0 分，是测量顺序造成的偏差，不是游戏机制。

   所以 `equipment_tier.use_in_score: false` —— 器材只按**张数** × 0.5 计，
   档位只记录（日志：`器材暴击（局内熟练度触发，瞬时状态）：金 N / 彩 N / 未暴击 N`）。
   张数仍按训练项各自计（张数是真实分布差异）。

**双背景回归**：`tools/test_equip.py` 新增「双背景」段 —— 真截图（黄背景 2 彩 / 蓝背景 1 彩）

## 5 默认选中项：进页面就能采，一次都不点（玩家 2026-11-24 11:55）

玩家原话：
> 进入的时候默认就是投射的，不用点击直接就能读数，如果这时候要去点击它，会直接变成选中。

所以训练项页的读数顺序被彻底改成「默认项优先、且只读不点」：

| 顺序 | 动作 | 说明 |
|---|---|---|
| ① | 找默认选中项 | `_selected_skill` 从深蓝高亮胶囊认出（浅蓝底/橙底两套皮肤都认；认不出返回 None） |
| ② | **先采它，全程不点击** | `_core_measure(..., how="default")`；采不到只重新取帧（`warmup=0.6` 重采一次），绝不补点 |
| ③ | 再逐个点开其余**有角标**的技能 | 没角标 = 没人，不采（见 §6） |

三个要点：

1. **为什么要先采**：旧实现虽然也判断了 `name == selected` 就不点，但读数顺序按胶囊 `cy` 从上往下。
   一旦排在前面的技能先被点开，画面就成了那个训练项的编队，轮到默认项时"采当前帧"采到的是别人的
   数据。W2D4「带经理加成 + 器材」的投射掉出候选池，根子就是这个顺序问题。
2. **默认项只在它有角标（有人）时才采**：没角标说明这一项没人，队友恒为 0，采它只是白烧几帧
   OCR，还可能把误读的名字当队友抬分。
3. **认不出高亮时**：所有带角标的训练项都点开读数（不特殊对待投射），靠排名选；收尾因为无法假定
   谁已选中，会点一次最优项再点「决定」。

证据侧：默认项的读数图落在 `core0_<技能>`（其余是 `core1_` 起），`DECIDE.txt` 里写明
「先进页面直接采默认帧、全程未点击」，读数失败则写「未采到，未参与排名」。
回归：`test_default_skill` 41 项，含「第一个动作必须是采默认项」「默认项一次都没被点」
「六项都没角标就不读数」「默认项没角标就不采」四类断言。

## 6 角标的含义：有人 / 没人（含一次走错的弯路）

### 6.1 定论

**角标 = 这一项有支援单位站台（有人）；没有角标 = 一定没人。**（玩家 2026-11-24 12:55）

所以训练项页的候选池只能是「带角标的技能」：

| 项 | 规则 |
|---|---|
| 有角标 | 进候选池，点开读队友 / 器材 / 失败率 |
| 没角标 | 队友恒为 0 → 不点、不采（点了也只是白烧几帧 OCR，还可能把误读的名字当队友抬分） |
| 六项全没角标 | 练哪项队友都是 0，区分只剩失败率与器材 → 不逐项点开，直接按默认项决定 |
| 默认选中项 | 只有在**它有角标**时才享受「先采、不点击」（见 §5），没人就不白采 |

### 6.2 走错的那一版（留档，别再犯）

第三轮实跑 8272 分后，我按「角标只是当天加成、与编队无关」的假设把候选池扩到
全部六项，还写了"平均每场只剩 3 个候选是最大失分点"。玩家当场纠正：**角标就是有人**。
那一版的代价是每场多 3 次点击 + 3 段读数（一轮多 8~10 分钟）、还多一份误读风险，
收益是 0 —— 已回滚。

第三轮实跑的关键数据仍然有效，只是**原因不是候选池**：

| 指标 | 结果 |
|---|---|
| 最终评分 | **8272**（目标 9000，差 728） |
| 训练项页 | 70 步（同一次训练会连续多步停在该页） |
| 完整训练项比较 | 27 场写出了「训练项排名」 |
| 「没有角标，跳过」 | 205 次 —— 这是**正常**的：那 205 项本来就没人 |
| 训练失败 | 3 次 |

其中两场此前被我误读，现在按"角标=有人"重新解释：

- `投射 MAX 失败率 77%` 那场排第一 —— 因为其他五项**都没人**，投射是唯一有队伍的；
  选它没选错，问题是全场只有这一个"有人"的选项，失败率高低没得挑。
- `体能 1.00 分` 单独成场 —— 同理，那天只有体能有人。

→ 结论：**候选池大小由游戏当天排的阵容决定，不是程序能扩的**。要冲 9000 得从别处找分。

### 6.3 这个结论对「9000 分」意味着什么

每场可选空间 = 当天有角标（有人）的训练项数，实测 1~4 项，平均 3 项。程序能做的是：
在有人的项里挑队友多、器材好、失败率低的；以及保证周一到周六不停训、不失败。
剩下要补的分只能在「训练次数 / 失败率 / 加成（经理增益、行为卡） / 比赛」上找，
不再是读数环节。

回归同步：`test_default_skill` 41 项，其中
「六项都没角标 → 不读数直接决定」「默认项没角标就不采」两条锁死这次的结论。

## 7 「一整天都没角标」不存在：那是残帧（玩家 2026-11-24 13:00 质疑）

### 7.1 玩家的问题

上一版把「六项都没角标」当成「今天没人」直接点决定。玩家问：

> 不可能会有一整天都没有角标的情况的，是不是角标识别不准

### 7.2 先量一遍：识别算法本身准不准

从 `logs/audit/` 抽 40 张真实训练项页帧（覆盖 11-23/11-24 两天、1600x900 与 1920x1080
两种分辨率），拿「全图橙色小圆」当基准（角标的图形特征太强：橙色圆 + 白色小人，
35x35 左右，不与别的 UI 混淆）：

| 指标 | 结果 |
|---|---|
| 基准角标总数 | 136 |
| 旧算法（OCR 框 ROI）判出 | **136，命中率 100%** |
| 新算法（全图搜 + 纵向就近）判出 | **136，命中率 100%** |
| 两者判出的「有角标训练项名」差异 | **0 / 40 张** |

→ 结论：**在稳定帧上，角标识别没有精度问题**。玩家的怀疑方向对了一半 —— 确实有
东西不准，但不准的不是算法，是**送进来比较的那一帧**。

### 7.3 真正的根因：残帧

把 575 张真实核心帧全扫一遍，统计每帧的角标个数：

| 角标数 | 1 | 2 | 3 | 4 | 5 | 6 |
|---|---|---|---|---|---|---|
| 帧数 | 3 | 55 | 198 | 259 | 58 | 2 |

**0 张是「全无」**，均值 3.5。也就是说「六个训练项全没人」在真实对局里根本不存在。

回看实跑第 3 轮那 3 次「六项都没角标」的现场日志，四条症状同秒连发：

```
没认出默认选中态（深蓝高亮）→ …
「投射」没有角标，跳过 …（六行）
六个训练项都没有角标 → 不逐项点开，只采默认选中项
所有候选都没读到训练项详情，按当前默认项决定
```

而且那一帧 OCR 只读到 **5 个训练项（缺防守）**。这是典型的**刚切页、胶囊和角标还在
淡入**的残帧 —— 切到训练项页时角标是从透明渐显的，判页与取帧在同一帧上完成，
抓到的就是 0.1~0.2 秒那一瞬间。

代价：那一整次训练没有做任何训练项比较，直接按默认项开训。

### 7.4 修法（两道）

1. **0 角标 = 坏帧，先重取帧**（`_do_training_core`）
   - 扫不到任何角标，或扫到但一个都与训练项行对不上（OCR 行纵向偏了），都算「角标不可用」；
   - 每次等 0.5s 重取，最多 3 次，重取成功就**用新帧 + 重算 rows / 默认项**继续；
   - 3 次仍不行才降级到按默认项决定，并记警告（不再是默认路径）。

2. **角标一对一分配**（新增 `_badges_for_rows`）
   - 原来逐行调 `_badge_near`，角标不消耗 → 训练项行间距实测 108px、半距 54px，
     而阈值一宽就会让**相邻两行抢同一个角标**，本来没人的项被判成有人；
   - 现在把所有 (行, 角标, dy) 排序后贪心分配，每个角标、每行各用一次；
   - 阈值收到 `0.055h`（1600x900 下 49.5px）：实测角标恒在训练项行上方 43~45px，
     而半行距 54px，刚好卡在两者之间。

顺带把搜索方式从「绑 OCR 框」改成「全图扫橙色小圆 + 纵向就近」：OCR 框偏过 99px
（日志有记录），框偏了 ROI 就偏，角标会整个跑出搜索窗。

### 7.6 还没验证的

```
WARNING ... 角标不可用（全图 0 个 / 训练项区 6 项 / 对上 0 项）→ 疑似坏帧，重取第 1 次

```
