## 4. 三个反复出现的教训

1. **认不出的页面不要兜底点按钮。** 两次严重翻车（游戏厅、误点出行）都是兜底逻辑太主动。
2. **文字指纹不够用。** 艺术字/无标题页必须靠图像特征（黄卡片、胶囊、卡片边框）。
3. **不要相信自己的推测。** 训练项名、地点名、队友/器材归属，全部以真实截图为准；自己编的权重等于给玩家埋雷。

## 6. 训练项打分为什么一直做不出来（2026-11-23 查清）

### 原来的假设

玩家口述 + 早期录屏（`demo/montage/cards_464.png`）看着像这样：

- 队友 = 球场上站着的角色名标签
- 器材 = 画面中间那排卡片
- 金光 / 彩光 = 卡片外框光效

于是 `_score_core` 写成 `队友数×1 + 金卡×1 + 彩卡×1.5`。

### 真机上是什么样

写了 `CoreSweepTask`（点一个训练项连拍 14 帧，逐帧 OCR）实测：

1. **这页一张卡片都没有。** 那批黄框卡片（球鞋 / 立绘，右上角带靴子/握手/盾牌角标）
   只在**点完「决定」后的开训动画**里出现 —— 也就是说，它是你选择的结果，不是选择依据。
   `find_cards()` 在训练项页恒返回 0 张，`equipment` 那一项永远加 0 分。
2. **球场上确实有队友，但只在选中某个训练项之后才出现**，而且各技能不同：
   投射会站真崎+百目鬼，弹跳站佐久间，运控/防守/意识可能一个人都没有。
3. **「球队经理」每场都在**，是场边角色，不是队友。
4. 过渡的那 1 秒里 OCR 会把相邻两个名字粘成一个框，队友数在 0~3 之间乱跳。

结论：原来 4 项权重里有 3 项拿不到数据，剩下的「队友数」还被粘连和经理污染 →
6 个训练项得分几乎全 0 或全相等 → 排序退化成「按 y 坐标选第一个」，
看起来就像「打分没生效」。

### 现在的打分

```
score = 队友数 × 1.0 + 训练项等级奖励(Lv.1=0 / Lv.2=0.5 / MAX=1.0)
score *= (1 - 失败率/100 × fail_weight)      # 失败=白扔体力，按比例打折
```

只用三个**真机上确实可读、且各技能确实不同**的信号：出场队友数、训练项等级、失败率。

读取方式：点开训练项 → 等 0.9s → 连拍 5 帧（每帧 OCR）→
队友名出现 ≥2 帧才算、失败率取众数、等级取众数。

实测日志（2026-11-23 05:24）：

```
「弹跳」LV.1 失败率=0%  队友1['佐久雅']        → 得分 1.00
「防守」LV.1 失败率=0%  队友1['闪堂']          → 得分 1.00
「运控」LV.1 失败率=0%  队友2['百目鬼','真崎'] → 得分 2.00   ← 选中
「防守」LV.1 失败率=28% 队友1['百目鬼']        → 得分 0.72   ← 失败率打折生效
「体能」LV.1 失败率=28% 队友2['闪堂','真崎']   → 得分 1.44
```

### 仍然不够好的地方

- 「佐久雅」这种是「佐久间」的 OCR 误识，数量对、名字错，暂时不影响打分。
- 队友多的技能是否真的收益更高，**玩家还没确认**。现在只是按「多一个队友多一份加成」推断，
  权重 1.0 随时可以在 `strategy.yaml` 的 `tuning.core_score` 里调。
- 如果以后发现器材真能提前看到（比如某个页面有预览），把 `equipment` 权重改回非 0 即可。

- 「休息」到底恢复多少精力仍未确认（文档写「不消耗精力，推进一天」）；目前策略是

## 8. 局外体力溢出 + 出行挑错档（2026-11-23 06:43 玩家现场发现）

### 8.1 「我的局外体力为什么溢出这么多」

**根因：补药逻辑不看剩余空间。**

三个叠加的毛病：

| # | 问题 | 后果 |
|---|---|---|
| 40 | 早期按「点了几次」计瓶数，不看专注实际涨没涨 | 06:01 那轮从 11/150 连喝 4 瓶 ×60 = 240，上限只有 150，**白扔一百多点** |
| 41 | 改成按涨幅计数后，仍然闭眼点最下面那行（大瓶 +60） | 只差 20 也喝 +60，每瓶浪费 40 |
| 42 | `stamina_refills` 是**整轮累计**，`每轮最多补专注次数=4` | 一轮 7 周只有 4 瓶额度，喝完后整轮不再补，后面训练开不了 |

修法（`_do_focus`）：

```
缺口 = 上限150 - 当前专注
缺口 ≥ 60   → 喝大瓶 +60
30 ≤ 缺口 < 60 → 喝小瓶 +30
缺口 < 30    → 一瓶都不喝，先关窗试训练
                （同一处反复弹窗 2 次才认，改喝最小瓶）
缺口 ≤ 0     → 直接关窗
```

- 「专注+N」按 **y 坐标**配对到同一行的「使用」按钮，所以不会误点到钻石那行
  （钻石行的按钮文字是价格「50」，本来也不叫「使用」）。
- 读不到数值时按缺口 30 兜底 → 只会选最小瓶，绝不会再灌 +60。
- `stamina_refills` 改为**每次弹窗**计，`close()` 时归零。

### 8.2 「差 21 点却选了 +70，而不是 +30 加属性」

**根因：拿标签上的原始数值当收益，没做溢出截断。**

旧逻辑 `eff = 标签值`（+70 → 70 分），所以 +70 永远赢；而玩家要的是
**能真正吃进精力条的部分**才算收益。现在统一走 `_reward_key`：

```
有效精力 = min(标签精力值, 130 - 当前精力)
优先级   = 笔记 > 训练项 > 有效精力 > 属性 > 零用钱
```

实测（缺口 21）：

| 选项 | 元组 | 数值 | 结果 |
|---|---|---|---|
| 野餐 精力+70 | (2, 21, 0, 0) | 20210 | |
| 划船 精力+30 属性+20 | (2, 21, 20, 0) | **20230** | ✅ 选中 |
| 散步 零用钱+ | (0, 0, 0, 1) | 0.1 | |
| 读书 笔记+1 | (4, 0, 0, 0) | 40000 | 最高 |
| 特训 技能+1 | (3, 0, 0, 0) | 30000 | 次高 |

顺带修掉：OCR 常把数字读丢，只剩「精力++」/「精力+」。原来 `_gain` 一律返回 1，
三档全打平 → 按坐标瞎选（日志里 06:20–06:26 全是「标签『精力++』精力+1」）。
现在按加号个数还原档位：单加 30 / 双加 70（属性 20 / 40）。

### 8.3 覆盖到的三处入口

`_do_trip`（地图）、`_do_go`（前往XX 列表）、`_score_option`（事件黄卡）
全部改为同一套 `_reward_key`，不再各自维护权重表 —— 之前就是三处各写一套，
改了一处漏了两处。

### 8.4 补记（06:49 玩家给出关键背景，推翻了「补满」的做法）

**玩家原话**：「那个电池一样的 202/150 就是体力啊，已经溢出到 202 了。
小瓶回 30，大瓶回 60。**每一次训练也只会消耗 30**。」

三件事一次说清：

| 事实 | 带来的改动 |
|---|---|
| 体力**允许溢出**，顶栏显示 202/150 | `_parse_ab` / `_read_stamina` 里的 `a <= b` 校验必须删掉，否则溢出值整条被丢 |
| OCR 吞斜杠时 `202150` 会退化成 `(20,150)` | 放宽到 `a <= cap*2`，`202150` 正确还原成 202 —— 这个误读正是「以为不够 → 又去补 → 越补越溢」的闭环 |
| 一次训练**只消耗 30** | 补药目标从「补满」改成「够 30 就停」，要补只喝小瓶 +30 |

`_do_focus` 现在的判定顺序：

```
读得到体力数值：
   a > 150（已溢出）或 a = 150  → 关窗，一滴不补
   a >= 30（够一次训练）        → 关窗，一滴不补
   a < 30                       → 喝小瓶 +30（小瓶没库存才喝大瓶 +60）
读不到数值：保守按「不够一次」处理，只喝最小瓶
```

这也解释了之前日志里 `局外专注 None/None`：不是 OCR 读不到，是读到了 `202/150`
又被 `a <= b` 判成非法值扔掉了。

### 8.5 第三次修正：读不到体力，根因在 OCR 文本长得不像规范数字

06:50 探针把大厅顶栏原样打出来，是这样：

```
「221/150+ü三」@(1564,48) w=580 h=45
```

两个坑叠在一起：

1. **正则锚定了结尾**：`^(\d{1,3})/(\d{2,3})\+?$` 要求以最多一个 `+` 结束，
   实测尾巴是「+ü三」，直接不匹配 → `_parse_ab` 返回 None → 体力永远读不到。
   改成 `re.search(r"(\d{1,3})/(\d{2,3})")`，不管后面粘了什么。
2. **不校验上限就认**：放宽之后页面上随便一个 `218/271`、`303/164`
   都被当成体力写进 `out_focus`，日志里 `221/150` 和 `303/164` 交替出现。
   新增 `_ab_kind(a, b)`：只认 `b` 贴着 150（±8）或 130（±8）的，
   其它一律 None。

同时把精力的上限固定成 130 常量，不再用读到的 `b` —— OCR 读到 134 时，
`if b > stamina_max` 的写法会让上限定死在 134，之后读到真正的 130 反而更新不了，
当前值就冻结在 108 不动（06:51 实测）。

验证（06:52 实跑）：

```

第 7 步  每日页   精力 90/130
第 9 步  训练项页 精力 44/130       ← 训练消耗后正常刷新
第 75 步 训练项页 精力 88/130
```

## 12. 选人页「没选满就停」+ 工作台（2026-11-23 09:00）

### #52 空白加号 = 还有东西没选，必须停下来

选人三连（选择队友 / 选择笔记 / 选择器材）里，**没选的槽位长这样**：

```
金色粗边框 + 近白底 + 中间一个黄色十字
```

器材页实测坐标 (0.555, 0.640)，尺寸约 187×181（1920×1080 下）。
已选中的卡片刚好相反：整块金黄、饱和度很高、里面是图标和「50」这种数字。

**判定条件（四条同时成立才认，缺一不可）**：

| # | 条件 | 阈值 |
|---|---|---|
| 1 | 金色描边轮廓，高度落在区间内 | `0.09H ≤ h ≤ 0.24H` |
| 2 | 接近方形 | `0.72 < w/h < 1.35` |
| 3 | 轮廓填充率够（是实心框不是碎金片） | `area/(w·h) ≥ 0.35` |
| 4 | 内部中间 46% 区域是近白 | 近白占比 ≥ 0.55 |
| 5 | 内部还留着黄色十字 | 金色像素占比 ≥ 0.08 |

**为什么不用 OCR**：这个「+」onnxocr 完全读不出来（跟公告页的关闭 × 一个毛病），

### #53 训练项读数「6 帧只用得上 2~4 帧」（玩家：是不是加个延时，别急着拍）

**现象**：日志连续出现 `训练项读数 4/6 → 2/6 → 0/6 帧可用`，最后一个训练项常常 0 帧，
于是 `全部训练项读数都失败，按当前默认项决定` —— 「挑最优训练项」有一半次数在空转。

**根因（两条叠加）**

1. 点完技能只等 0.9s 就开始连拍，而点开的过渡动画约 1 秒，前几帧全是动画中间态：
   名字标签还在淡入、训练项详情没展开 → 被判「不像训练项页」扔掉。
2. 判定本身太严：要求右侧**至少认出 2 个训练项名**，可面板一展开就把右列盖住了，
   `hits` 掉到 0~1，正常帧也被判废；废帧还占「6 帧」的配额，越到后面的技能越惨。

**改法（第二版，实机打回过一次）**

- 第一版按玩家建议「先等 1.2s 再拍」，结果**更差**：10:05 那轮三个训练项全是
  「6 帧有效但读不到任何数据」——等到的是浮层收走之后的空页面。
  CoreSweepTask 05:14 的结论才是对的：加成浮层只存在 **1~2 秒**。
- 定稿是「**早拍、密拍**」：`_sample_core(warmup=0.15, gap=0.18, frames=10)`，
  调用处不再额外等待；覆盖 0.15~1.95s 这个窗口。
- 废帧**不占配额**：`while used < 10 and tries < 14`，避免中途帧把配额吃光。
- 判定放宽：训练项名 ≥1 / 有「失败率」/ 有 Lv·MAX / 场上 ≥2 个队友名，任一命中就算有效帧。
- 凑够 3 帧失败率 + 3 帧名字就提前收工；日志 `训练项读数 N/10 帧有效（试了 X 次）`。

**顺带定的三条口径（玩家 2026-11-23）**

- 训练项等级**不参与计分**：`level_bonus` 三档全 0，仍读出来打日志。
- 失败率仍是**乘法折扣**：`分 ×(1 - 失败率/100)`，30% → 打七折、50% → 打五折。
- 失败率**全部** >30% 且商店确认没有精力道具 → 强制改练「意识」（成功率最高）；
  有技能没读到失败率、或本期没进过商店 → 这条不生效，按原排名。

单测：`tools/test_core.py`（计分 4 条 + 风险规则 6 条，全过）。

### #66 「笔记」从来买不到：主循环抢先把 notes_done 置真，把购买路径锁死（2026-11-26）

**玩家问**：「上一轮买到笔记了吗？运行这么多次有买到过笔记吗？」

**答案：一次都没有。全部日志里 `拿到笔记` 恒为 0，`[探笔记] 已买下` 从未出现。**

更关键的是：不是运气差。**至少两次笔记就摆在扭蛋三选一里，被代码自己放掉了。**

证据（原始日志，一字未改）：

```
2026-11-24 11:20:59,850  [探笔记] 扭蛋三选一没有「笔记/继承」→ 两级右上角退回

```

选项里明明是 `笔记继承`，下一行却写「没有」。11-25 14:36:42 又来一次一模一样的。

**根因（两处互相咬）**：

1. 主循环（原 5631 行）只要**画面全文**里出现「笔记继承」四个字就 `notes_done = True`。
   可这四个字本来就印在步行街扭蛋的**选项**上 —— 一出现就先判成「本轮已拿过」。
2. `_do_egg_machine` 里写的是 `if not hits or self.notes_done:`，两种情况共用一句
   「没有「笔记/继承」」的日志。于是 `notes_done` 为真时，日志把「明明有、但我不买」
   谎报成「没有」，事后复盘完全看不出来。

- 删掉主循环那条预置位。是否真拿到，只由**买成功那一刻**决定（`_do_egg_machine`
  末尾 `notes_done = True`）。「笔记继承」出现在选项列表里不再有任何副作用。
- `if not hits or self.notes_done` 拆成两条，日志各说实话：
  - 没命中 → 「没有「笔记/继承」」（原文案）；
  - 命中但本轮已拿过 → 「扭蛋里有 [..]，但本轮已经拿过笔记 → 不买」。
- `stat["note"]` 从「命中时 +1」移到「买下并确认后 +1」，
  摘要里的「拿到笔记 N 次」才是真数（以前那栏实际是命中数）。

**影响面**：只影响步行街探笔记这条路，训练/打分/读数链路不动。

## #70 器材不是 OCR 读的；经理也不是常驻（2026-11-26 玩家纠正）

### ① 器材：确认走图像，不走 OCR —— 但「只是几张 + 品质」不等于「知道是什么器材」

代码事实：`src/core/cards.py` 全程没有 OCR。链路是
`金边掩膜 ∪ 高饱和掩膜 → 形态学闭运算 → 轮廓 → 尺寸/长宽比过滤 → 双掩膜 IoU 合并`，
再由 `card_glow()` 看内圈+外圈的冷暖色判「普 / 彩」。卡面上只有插画和图标
（球、护腕、人物…），玩家看到的「像个字」是图标形状，没有任何可读文本 ——
所以这页**不可能也不应该**用 OCR 认器材。

能读到：几张、金/彩/普。读不到：具体是哪件器材。
要读「哪件」只能做图标模板匹配（`ok_templates` 那套），收益不明，暂不做。

### ② 器材是「按项分布」的，不是场级固定 —— 我上一版改错了，已回退

第一版我按「器材选择页定死、整场共用」处理，把每项的张数统一成一个值。
**玩家当天就纠正了**：「器材是开局先选好五个，训练过程中这些器材可能分布在各个不同的
训练项目里面，也有可能不出现，所以不是固定的；上限也不是三个，四五个也可能。」

→ 已回退成**按每个训练项各自读数计分**（那 52% 的差异是真实差异，不是抖动）。
→ `MAX_CARDS` 从 3 改成 **5**，ROI 右边界 0.63 → 0.66 容纳 5 张横排。
→ `last_equip_count` 仍取整场最大张数，给商店「器材暴击」判断用。

## #73 金/普分开了：采样点要压在最外沿（2026-11-26 玩家给手机截图，最终解）

**玩家原话**：「这个左边就是普通的，右边就是金光，你看一下，这是我用手机截的图，

图里并排两张卡：左边球鞋＝**浅奶油黄细框、外面什么都没有**；
右边「希雅＋大星星」＝**浓橙金粗框、外面还有一圈橙金光晕**。

### 之前为什么一直分不开 —— 采样点差了几像素

我试过好几轮都得到「单峰」，于是写下「金和普在颜色上分不开」。

```
bbox 边界 ───────────────  ← 差的就是这几 px

内缩 2~6px  ── 卡面底色（**所有卡都是橙黄，S≈170**）        ← 旧采样点
内缩 10%+   ── 卡面插画
```

卡面底色本身就是橙黄，所以只要采样圈越过框线，读到的永远是 170 上下的同一个数 ——
不分金普、也不分卡种，当然只剩单峰。**「单峰」是采样错误的假象，不是游戏里真没有金。**

## #74 彩卡判据：只看「青蓝紫占比」会把蓝色球场全判成彩（2026-11-26 玩家第四次纠正）

玩家：「彩色也不止 1% 这么低吧，彩色实际是长这样的。」（附室内双彩卡截图）
接着又补一句：「背景也是有可能会变，除了那种黄色的背景之外，还会有这种蓝色的背景，
你要测试一下这两种都能区分出来。」（附室外蓝色球场截图）

### 彩卡到底长什么样

不是「框线偏色」，是**围着整张卡一圈完整的彩虹光晕**（青→绿→黄→粉→紫），
比金卡的「浓橙金粗框 + 橙色外光晕」多了一整圈冷色。两张图里 3 张卡都是这样。

### 原来的判据为什么错

`rainbow = 框线上 H78~165（青蓝紫）的占比 ≥ 0.30`。在室内木地板上成立（彩 0.77~0.91、非彩 ≤0.06）。
但玩家说的蓝色背景一测就炸：

| 采样来源 | rainbow | warm | nbig |
|---|---|---|---|
| 彩卡（黄背景） | 0.66~0.90 | 0.08~0.15 | 4~7 |
| 彩卡（蓝背景） | 0.66~0.81 | 0.06~0.30 | 3~6 |
| **纯蓝地板** | **1.00** | **0.00** | **1** |
| **纯蓝天** | **0.96~1.00** | **0.00** | **1** |
| 金卡 | 0.00 | 0.98 | 1 |
| 普卡 | 0.00~0.09 | 0.93~1.00 | 1~2 |

蓝地板/蓝天的青蓝紫占比是 **1.00**，比彩卡还高 —— 只看这个指标，室外球场的每张卡都会被判成彩。

彩虹的本质是**多色相 + 冷暖共存**，单色背景只有一个色相桶、暖色为 0。
所以判据改成三条件同时成立：

```
彩 = rainbow ≥ 0.30  且  warm ≥ 0.05  且  nbig ≥ 3
```

`nbig` = 占比 ≥8% 的色相桶个数（H 每 11 一格，共 16 格）。

### 第二个坑：bbox 偏大时，最外沿读不到彩虹

彩卡的光晕有厚度，会把掩膜轮廓撑大，致密度只有 0.69~0.88（普通卡 0.93+）。
玩家截图里并排那张篮球架彩卡，**bbox 最外沿 1~3px 的 rainbow 只有 0.21，扫到 7px 才是 0.79**。
固定采样会把它漏成「普」。

改成扫 **bbox 内 0.8%~11% 的 9 圈**，取「像彩虹」（多色相 + 冷暖共存）的圈里 rainbow 最大的那个：

| | 多圈最大 rainbow |
|---|---|
| 普卡 519 张 | p99 = 0.07，max = 0.09 |
| 金卡 296 张 | 全部 0.00 |
| 彩卡 11 张 | 0.63~0.94 |

判彩 0 张误伤、11 张全中。玩家截图 3 张卡（含那张 bbox 外扩的）全部判彩。

### 第三个坑：彩卡会被致密度 0.66 整张滤掉

玩家截图里那张篮球架彩卡，`extent = 0.41`，低于 `MIN_EXTENT=0.66`，**整张卡漏检**。
（黄背景那张图原来只检出 1 张，应为 2 张。）

致密度本来是用来滤「+33/+36」火焰伤害数字（0.55~0.62）的，不能一律放宽。
所以只给**强彩签名**开口：

```
extent ∈ [0.35, 0.66) 时，要求 rainbow ≥ 0.55 且 多色相 且 冷暖共存 才认作卡
```

被滤掉的那 112 个低致密度候选里，28 个有「彩特征」但全是右侧训练项按钮 / 笔记页商品卡
（rainbow ≤0.48，warm 0.48~0.70）—— 0.55 这道门正好挡住。修完黄背景图检出 2/2。

### 试过但**否掉**的方案：金判据改多圈取最大值

想让金也抗 bbox 偏差，试了「扫 8 圈取 edge_sat 最大」：

| | 固定最外沿 1 圈 | 多圈取 max |
|---|---|---|
| 普卡 | p50 159 / max 176 | **p50 184 / max 244** |
| 金卡 | p50 209 / max 225 | p50 209 / max 225 |

所以**金只能在最外沿读，不能取多圈最大值**；`edge_sat` 对 bbox 精度敏感是它的固有代价，

| 之前的疑点 | 现在的解释 |
|---|---|
| 同一件器材（球鞋 / 篮球 / 双节棍）既有普框版本，又有金 / 彩框版本 | 是**同一件器材的不同暴击状态**，不是两种卡 |
| 同一训练项 20 秒内读数 金→普→普→普普金→普 | 暴击在闪，不是换卡、也不是淡入淡出 |
| 826 张卡里彩只占 1.3%，玩家却觉得「彩很多」 | 1.3% 只是**那批帧的瞬时占比**；熟练度越高，金/彩 拍到的比例越高 |
| 普 24 张抽样里只有 4 种图标、彩 11 张里有 5 种 | 同件器材反复以不同暴击状态出现 |

### 由此产生的规则改动（唯一实质改动）

**暴击档位不再参与训练项排名**，器材只按**张数**计 0.5/张：

```yaml
equipment: 0.5            # 每张卡的基础分
equipment_tier:
  use_in_score: false     # 玩家 2026-11-26 定：暴击档位不进排名
  普: 0.5
  金: 1.0
  彩: 1.5
```

两条理由：

1. **它是随机事件的一次抽样**，不代表这个训练项值多少分。
2. **采样顺序会造出假优势** —— 5 个训练项是**依次**点开采的（默认项 → 其余逐个），
   而熟练度在一局里持续上涨，越后采的项越容易拍到金/彩。按档位计分等于
   「谁最后被采谁占便宜」，这是一种测量偏差，不是游戏机制。
   （数学上也等价：暴击与选项无关，期望值为常数，计进去只加噪声。）

档位仍然**照旧读、照旧打日志**，日志文案改成：

```
器材暴击（局内熟练度触发，瞬时状态）：金 2 张 / 彩 1 张 / 未暴击 3 张 → 不参与排名，只记录
```

`use_in_score: true` 可以恢复旧行为（按档位计分），但请先想清楚上面第 2 条。

### 不改的部分

- 识别判据一行没动：金 = 最外沿 `edge_sat ≥ 185`；彩 = 多圈 `rainbow≥0.30 且 warm≥0.05 且 nbig≥3`。
- **器材张数仍按训练项各自计分**（玩家 2026-11-26 早前口径：器材分布在不同训练项里，
  也可能不出现）—— 张数是真实差异，档位才不是。
- MAX 仍然不作判据（玩家：「Max 不是一定有的」）。
