# 13 · 规则怎么改（给接手的人看）

> 一句话：**规则都在 `config/strategy.yaml` 一个文件里，工作台「运行设置」是它的图形界面；
> 改数值用界面，加新规则加键 + 在代码里读一次。没有第二套状态。**

---

## 1 配置文件现在长什么样

只有一个玩法规则文件：`config/strategy.yaml`（307 行，分五段）。

| 段 | 作用 | 谁在读 |
|---|---|---|
| `rules:` / `plans:` / `safety:` | 早期的「条件→方案」框架，**现在基本不用** | 保留兼容，别删 |
| `tuning:` | **真正生效的规则全在这里**，分 15 个子块 | `AutoTask._tuning()` 读，`rule` 代码逐键取 |
| `routes:` | 角色分支预留位（希雅/未央/铃兰/苏晚），现在是空的 | 有内容才生效 |

`tuning` 下的 15 块（就是你现在能调的全部旋钮）：

| 块 | 管什么 |
|---|---|
| `egg` / `trip` / `enhance` / `behavior_card` | 扭蛋、出行、经理增益、行为卡偏好 |
| `core_score` | **训练项打分**（队友/器材/失败率/意识加权/主训识别） |
| `event` | 随机事件五档优先级 + 关键词 + 数值还原 |
| `shop` | 商店白名单、价格上限、周日不进店 |
| `stamina` | 体力药水开关 + 每轮瓶数 |
| `unknown` | 未知页指纹表 + 兜底动作 |
| `summary` / `runlog` / `resume` | 运行摘要 / **运行记录** / 断点续跑 |
| `pick_slots` / `loop` / `stock` | 空槽策略 / 循环轮数 / 炒股小游戏 |

另外两个文件**不是规则**，别混：
- `configs/AutoTask.json` —— 任务运行参数（最大步数、训练精力下限、专注恢复…），也是工作台在改。
- `config/workbench.yaml` —— 工作台自己的设置（游戏路径、进程名）。

## 2 能图形化编写吗？—— 能改，分两种

### ✅ 常用 19 项：工作台「运行设置」直接点

打开工作台（双击 `run_workbench.bat` 或 `python -m workbench`）→ 左边「运行设置」标签，
19 个控件按 **运行 / 精力与药水 / 编队与暂停 / 商店 / 训练打分** 五组排好：

- 循环轮数、最大步数、未知页兜底、保存截图
- 允许用体力药水、每轮瓶数、训练精力下限、买药阈值、意识加权
- 检查空槽、发现空位怎么办、停下时弹提示
- 商店自动买、不进店的星期、一次最多买几件
- 失败率上限、出行先看笔记
- **经理增益选哪个**（最高加成 / 第一个）、**读数失败就停下**（2026-11-26 新增）

改完点「**保存到配置**」→ 自动备份到 `config/.backup/`（留最近 20 份）再写回 yaml。
**界面只是 yaml 的编辑器**，命令行跑和界面跑读的是同一份文件，行为一定一致。

### 🟡 其余键：没有控件，改 yaml 原文

工作台「规则原文」标签能看当前内容，但**只读**。要改这些（比如 `core_score.teammate` 权重、
`event.priority` 五档顺序、`shop.rules` 价格），两种方式：

1. 点「打开文件」用记事本改（推荐，改前自己另存一份）；
2. 直接编辑 `config/strategy.yaml`。

改完回工作台点「重新读取」，或重启工作台 —— 脚本每次启动都会重新读文件。

> 为什么不做成全控件？这些键是「调节参数」，改的人极少且需要看上下文注释（文件里每条都写了
> 为什么定这个值）。全铺成控件反而把 307 行的决策记录淹掉。真有高频需求再加。

## 3 别人想加一条新规则，怎么走

### 情况 A：只是现有规则换个值 / 换个顺序

**不用改代码。** 工作台点几下，或改 yaml，收工。例如「失败率上限从 30 改到 40」，
在「运行设置 → 训练打分」改数字保存即可。

### 情况 B：加一个 yaml 里还没有的新键

两步：

1. **在 `strategy.yaml` 对应块里加键**，带上注释说明来源：
   ```yaml
   core_score:
     teammate: 1.0
     my_new_rule: 0.5    # 2026-11-23 玩家：xxx，为什么
   ```
2. **在 `AutoTask.py` 里读一次它**，在决策点用起来：
   ```python
   cfg = self._tuning().get("core_score", {})
   v = cfg.get("my_new_rule", 0.5)   # 一定给默认值，老配置没有这键也不能崩
   ```
   放哪个函数由规则性质决定：打分进 `_score_core` / `_do_training_core`，
   商店进 `_do_shop`，事件进 `_reward_key`。搜索同类键在哪读，照着放。

⚠️ 三个坑：
- **键名写错 = 静默失效**。改完在日志里搜你的规则名，确认有输出才叫生效。
  `tools/test_rules_config.py` 会校验一批关键键存在。
- **一定要给默认值**：`cfg.get(key, 默认值)`，别直接 `cfg[key]`，否则旧配置文件一跑就崩。
- **注释别怕长**：这个文件里每条规则都记着「玩家哪天说的、为什么」，这是个决策日志，不是纯配置。
  工作台的保存逻辑是逐行定点改写，注释和列对齐都会保留（见 `workbench/settings.py`）。

### 情况 C：加一个全新的决策页面 / 状态机分支

改 `AutoTask._classify()`（认页面）和 `_run_loop()` 里的 `elif page == ...`（怎么处理），
比加键大一级。做完补一个离线测试（`tools/test_*.py` 的套路：Stub + 假数据，不开游戏）。

## 4 运行记录怎么看（本次新加）

工作台第四个标签「**运行记录**」：

- 顶部显示最近一次运行的时间、状态、**完成几轮/共几轮、训练几次、精力/专注从多少到多少、喝了几瓶药**；
- 下面表格逐条列**每次选课的最终得分**（就是训练项打分，含失败率）；
- 数据存在 `logs/runs.jsonl`，一行一条，崩了也不丢已写的；中途断线续跑会接着同一次运行记。

关掉：在 `strategy.yaml` 的 `tuning.runlog.enabled` 改 `false`。

## 5 一句话速查

| 我想… | 去哪 |
|---|---|
| 改轮数/药水/空槽/商店/失败率 | 工作台「运行设置」 |
| 改权重/优先级/价格/关键词 | `config/strategy.yaml` 的 `tuning` 段 |
| 加新键 | yaml 加键 + 代码里 `cfg.get(键, 默认值)` 读一次 |
| 加新页面逻辑 | `AutoTask._classify()` + `_run_loop()` |
| 看跑得怎么样 | 工作台「运行记录」/ `logs/summary_*.txt` |
| 回退改错的配置 | `config/.backup/` 里按时间挑一份覆盖回去 |
