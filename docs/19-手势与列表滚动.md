# 19 手势与列表滚动

> 来源：`demo/session_1127_152728`（2026-11-27 15:27，133 秒 / 76 个节点 / 18 个动作 / 5 次拖拽）。
> 坐标一律是**相对游戏窗口的归一化值**（0~1），和 `click_relative` 同一套，换分辨率不用改。

## 0. 一句话结论

训练流程里所有卡片列表（选人 / 队友 / 笔记 / 器材 / 商店货架）都是**纵向 ScrollRect**：
按住往上拖能滚，**滚轮也能滚**。滚轮每格固定、没有惯性残余；拖拽松手后会惯性滑一段，
落点会差半行（实测差约半行）。所以**脚本里用滚轮，不用拖拽**。

## 4. 商店货架（已实现）

- 货架区：x 0.10 ~ 0.61，y 0.15 ~ 0.58；右侧是选中商品的详情面板（不要在这儿滚）
- 滚动落点用 **(0.35, 0.38)**，落在货架中上部，避开卡片边缘
- 实现：`AutoTask._shop_scan()` —— **进店先把货架滚回顶部**（`-pages*wheel_notches`），
  再从顶逐屏往下 OCR 到底，最后再滚回顶部，按第一屏坐标点击；
  点击前用 `_shop_find_now()` 按名字重新定位（滚动后坐标会变）
- 2026-11-28 修正：以前只往下滚、不回顶，货架若停在中间，**屏幕上面那半屏永远读不到**
  （实跑漏掉第二行的「白神的笔记」）。现在上下都滚，并用「相邻两屏文本指纹是否相同」
  判断是否真的滚到头（`_shop_sig()`），不再靠「有没有新商品」瞎猜
- 配置：`tuning.shop.scroll_scan / scan_pages / wheel_notches`
- **本次上新会有一件 0 元的「本次训练」专属商品**（如「白神的笔记」）。
  它有两个用途：① 验证滚到底没有（它常在最后一行）；② **本身要买** —— 白送，
  `_shop_offers()` 里价格 0 一律归 `free`，不依赖名字分类。
  别把它写进 `strategy.yaml` 的 `order`/`rules`（不是通用商品，条件是「价格 = 0」）
